Chọn API và cách sử dụng

TEI Shield trả lời: “Các check được chọn vừa quan sát thấy dấu hiệu gì trên thiết bị?” App chọn detector và nhận snapshot. API assessment không cần API key, URL dịch vụ hay enrollment; không có điểm rủi ro tổng hợp, màn hình chặn hoặc tự upload dữ liệu.

Tài liệu này đối chiếu source trong repository: native SDK 0.1.0, wrapper Expo/Flutter 0.1.9. Đây là version trong manifest, không phải xác nhận package hiện có trên registry hay binary cũ đã có đầy đủ API.

Chọn wrapper theo host: Kotlin cho Android, Swift cho iOS, Expo Modules cho React Native/Expo, Dart cho Flutter. Các wrapper gọi chung native implementation; cài nhiều wrapper không làm tăng khả năng phát hiện. JS/Dart tự quản lý lifecycle và gọi native one-shot, nên không cần thêm native foreground observer cho cùng luồng.

Lời gọi đầu tiên không cần certificate​

Sau khi cài theo nền tảng, gọi trong coroutine/hàm async:

import dev.tei.shield.ShieldCheck
import dev.tei.shield.TeiShield

// applicationContext do Android application/activity cung cấp.
val signal = TeiShield.check(applicationContext, ShieldCheck.EMULATOR)
import TEIShield
let signal = await TeiShield.check(.emulator)
import {check} from '@teiresource/shield-expo';
const signal = await check('emulator');
import 'package:tei_shield_flutter/tei_shield_flutter.dart';
// Nếu gọi trước runApp(), chạy WidgetsFlutterBinding.ensureInitialized() trước.
final signal = await TeiShield.check(ShieldCheck.emulator);

Kết quả gồm code, status, confidence. iOS Simulator trả emulator: detected, confidence high. Android dùng heuristic build properties, confidence medium; kết quả âm tính không loại trừ mọi emulator. Xem danh mục detector.

Chọn đúng lượng công việc​

Danh sách rỗng chạy không detector nào. Expo assess() và Flutter TeiShield.assess() mặc định là danh sách rỗng, không có nghĩa “quét tất cả”. Static assessment native yêu cầu truyền options.

Ví dụ nhỏ dùng chung hai nền tảng là emulator và sdkTextIntegrity; có thể thêm injectedImages nếu app cần dấu hiệu thư viện được nạp. Đây là lựa chọn minh họa, không phải profile bảo vệ được chứng nhận. Chọn tất cả cũng bao gồm check không hỗ trợ.

client.assess(override) thay toàn bộ options cho một lần, không merge identity đã lưu. Nếu override trên Android chọn appIdentity, truyền identity lại. Riêng framework client.check('appIdentity') / client.check(ShieldCheck.appIdentity) dùng identity mặc định. Override cập nhật lastAssessment, nhưng không đổi lựa chọn mặc định.

Biến kết quả thành hành vi của app​

Ví dụ policy sau là code của app, không phải API hay thang điểm có sẵn trong SDK:

import type {Assessment, ShieldCheck} from '@teiresource/shield-expo';

type Review = 'indicator-observed' | 'incomplete' | 'no-indicator-observed';
function review(result: Assessment, required: readonly ShieldCheck[]): Review {
  if (result.schemaVersion !== 1 || required.length === 0) return 'incomplete';
  const signals = required.map(code => result.signals.find(s => s.code === code));
  if (signals.some(s => s?.status === 'detected')) return 'indicator-observed';
  if (signals.some(s => !s || s.status !== 'notDetected')) return 'incomplete';
  return 'no-indicator-observed';
}

indicator-observed: app đánh giá ngữ cảnh hoặc yêu cầu xác minh bổ sung. incomplete: thiếu check, không hỗ trợ, lỗi hoặc schema lạ cần được xử lý riêng. no-indicator-observed: các check bắt buộc chưa thấy dấu hiệu, không có nghĩa thiết bị chắc chắn an toàn. App vẫn thực hiện quy tắc xác thực/phân quyền thông thường trong mọi nhánh. SDK không cung cấp UI hay thao tác server cho các nhánh này.

lastAssessment không có timestamp/expiry. Nếu cần độ mới, app tự lưu thời điểm nhận và gọi lại trước thao tác cần kiểm tra. durationMs chỉ đo assessment native, không gồm chờ queue, bridge, render UI hay độ trễ toàn luồng.

Quản lý vòng đời​

Giữ một instance/client ở scope app hoặc session, không tạo lại theo mỗi lần render. Hai cờ run policy configurable mặc định false; tạo client thành công vẫn có thể chưa có lastAssessment. API native legacy có mặc định khác, xem API native.

Bắt lỗi lời gọi thủ công bằng try/catch. Expo gửi lỗi tự động tới onError; Flutter gửi vào error channel của stream assessments. Stream Flutter không replay kết quả lúc initialize: đọc lastAssessment ngay sau khởi tạo. SDK native chỉ cung cấp snapshot property, không tự phát sự kiện cập nhật UI.

Đóng owner và hủy subscription khi scope kết thúc. Semantics của close() khác nhau giữa nền tảng; xem API framework. Foreground assessment không phải background service hay quét liên tục.

Đọc tiếp​

  • Danh mục detector: cách hoạt động, confidence, giới hạn, nền tảng.
  • API native và API framework: chữ ký hàm, mặc định, kết quả, lifecycle.
  • Protocol helper và C ABI: tiện ích cấp thấp và phạm vi chưa triển khai.
  • Xử lý lỗi: lỗi cài đặt, cấu hình, status và lifecycle.
