React Native / Expo 集成

@teiresource/shield-expo 模块直接通过 npm registry 分发。Android 从 Maven Central 解析 SDK io.github.tranvanloccntt123:shield:0.1.0；Swift bridge 使用 package 中包含的 XCFramework。TypeScript 负责 detector 选择、client 和生命周期管理。

该模块使用 Expo Modules API，适用于已安装 Expo Modules 的 Expo 或 React Native 项目。必须使用 development/native build；标准 Expo Go 不包含 TEI Shield 的 native binary。基准示例使用 Expo SDK 55、React Native 0.83 和 React 19.2；需要 Android API 26+ 与 iOS 15.1+。

在 Expo 应用中安装​

npx expo install @teiresource/shield-expo
npx expo install expo-dev-client

将 config plugin 加入 app.json：

app.json
{
  "expo": {
    "plugins": ["@teiresource/shield-expo"]
  }
}

生成 native project 并运行 development build：

npx expo prebuild
npx expo run:android
# 或：
npx expo run:ios

AAR 支持 arm64-v8a 和 x86_64。发布前，在 Gradle properties 中设置 reactNativeArchitectures=arm64-v8a,x86_64，或使用 expo-build-properties 的 android.buildArchs: ['arm64-v8a', 'x86_64']。Autolinking 会自动注册 Kotlin/Swift 模块。使用 EAS Build 时，Gradle 从 Maven Central 解析 SDK，iOS XCFramework 仍位于 npm package 中。安装或升级 package 后重新运行 npx expo prebuild。

已有 native project 的 React Native​

npm install @teiresource/shield-expo
npx pod-install

如果项目尚未使用 Expo Modules，请先安装 Expo Modules。Android minSdk 保持 >= 26，iOS target 保持 >= 15.1。无需手动注册 ReactPackage；Expo Modules autolinking 会处理。Android host 必须在 dependencyResolutionManagement.repositories 中包含 google() 和 mavenCentral()。

使用 Hermes 和 R8 保护 release​

React Native/Expo 的 release build 应启用两层保护：

  • Hermes 将 JavaScript/TypeScript 编译为 bytecode，而不是在 APK 中打包易读的 source。
  • R8 对 native Java/Kotlin 代码进行 shrink、优化和 obfuscate，将 class、method 和 field 重命名为 a、b、c 等短名称。

R8 不会让逆向工程变得不可能，但会显著增加 APK 分析难度。它保护 release artifact，不能替代服务端认证、API 控制和避免硬编码 secret。

为 Expo 配置 R8​

npx expo install expo-build-properties

在 app.json 或 app.config.js 中加入：

app.json
{
  "expo": {
    "plugins": [
      "@teiresource/shield-expo",
      [
        "expo-build-properties",
        {
          "android": {
            "enableMinifyInReleaseBuilds": true,
            "enableShrinkResourcesInReleaseBuilds": true
          }
        }
      ]
    ]
  }
}

enableMinifyInReleaseBuilds 为 release build 启用 R8。enableShrinkResourcesInReleaseBuilds 移除未使用的资源，以缩小 APK。当前 Expo SDK 应使用这些属性，而不是旧的 enableProguardInReleaseBuilds。

Build 与验证​

如果项目已有由旧配置生成的 android/ 目录，请先重新生成：

npx expo prebuild
npx expo run:android --variant release

运行 npx expo prebuild 应用 plugin 配置并检查 diff。只有 native project 可从配置完全重建且手工修改已保存时才使用 npx expo prebuild --clean；clean 会替换 native 目录。手工维护的 native project 应直接修改相应 Gradle 配置。

# R8 运行后应存在 mapping file
ls -la android/app/build/outputs/mapping/release/mapping.txt

# 应看到 minifyEnabled true
grep "minifyEnabled" android/app/build.gradle

安全保存 mapping.txt，以便之后解码 crash stack trace。也可以使用 JADX 检查 APK：

jadx android/app/build/outputs/apk/release/app-release.apk -d /tmp/decompiled
ls /tmp/decompiled/sources/

必须进行 release 测试​

R8 可能移除通过 reflection 访问的 class。请将 release build 安装到真实设备，测试模块初始化、autolinking、assessment 及其他 native library。如果 debug 正常而 release 崩溃，请检查：

adb logcat | grep -i "error\|crash\|exception"

为出错的 library 添加必要的 keep rule，并保留 TEI Shield 的 consumer rule。完整的 release checklist 见验证指南。

参考原文：Enabling Code Obfuscation in Expo React Native: R8 Shrinking & Obfuscation。

单次检查​

import {assess, check} from '@teiresource/shield-expo';

const emulator = await check('emulator');
const result = await assess({checks: ['emulator', 'sdkTextIntegrity']});
const empty = await assess(); // signals: []; 不会初始化 observer

SHIELD_CHECKS 包含 12 个 public code。结果只包含被选择的 detector；TypeScript 和 native 都会拒绝无效 code。

从客户端应用配置​

import {createClient, SHIELD_CHECKS} from '@teiresource/shield-expo';

const identity = {
  expectedPackage: 'com.company.mobile',
  signingCertificateSha256: [releaseCertificateSha256, nextCertificateSha256],
};

const client = await createClient({
  options: {
    checks: ['appIdentity', 'emulator', 'sdkTextIntegrity'],
    appIdentity: identity,
  },
  runPolicy: {assessOnInitialize: false, reassessOnForeground: true},
  onAssessment: assessment => appRiskPolicy.consume(assessment),
  onError: error => reportAssessmentFailure(error),
});

const configured = await client.assess();
const once = await client.assess({checks: ['debugger']});
const all = await client.assess({checks: SHIELD_CHECKS, appIdentity: identity});
client.close();

Android 在选择 appIdentity 时要求非空的 expectedPackage 和至少一个小写 64 字符 SHA-256 hex digest。所有 current signer 都必须在 allowlist 中。iOS 的 appIdentity 返回 unsupported。unsupported/error 不是 notDetected，应用应自行决定 fallback、step-up 和 telemetry policy。

Schema 与 policy​

type Assessment = {
  schemaVersion: number;
  signals: {code: string; status: 'detected' | 'notDetected' | 'unsupported' | 'error'; confidence: string}[];
  durationMs: number;
};

Bridge 保留 status 和 confidence，不会锁定应用、终止进程、显示 UI 或发送网络请求。应用根据 detector、confidence 和上下文决定 policy。iOS 不支持 appIdentity、storeAttestation、missingMotionSensors 和 batteryUnavailable。

运行示例与测试​

cd packages/tei-shield-expo
npm ci
npm run build
npm test
cd example
npm install
npx expo prebuild
npx expo run:android
# 或 npx expo run:ios

TypeScript 测试使用 fake runtime 检查 contract 和 lifecycle。仍需按照验证指南在真实设备上测试 development build、release/R8、foreground 行为和真实签名证书。
