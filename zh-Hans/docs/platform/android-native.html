Android native 集成

本指南使用 Maven Central 的 Android SDK io.github.tranvanloccntt123:shield:0.1.0。Kotlin API 运行在 Android 8+，native library 提供 arm64-v8a 和 x86_64。

要求​

ComponentSDK version
minSdk26（Android 8.0）
compileSdk示例项目为 35
JDK/KotlinJDK 17，Kotlin JVM target 17
AAR ABIarm64-v8a、x86_64
Runtime dependencyCoroutines Android 1.10.2、Lifecycle Process 2.8.7

从 source 构建 SDK 时，还需 Android NDK 28.2.13676358 和 CMake 3.22.1。仅使用 Maven dependency 时，app 不需要集成 CMake/NDK。

添加 Maven dependency​

确保 app project 在 dependencyResolutionManagement 中有 google() 和 mavenCentral()：

settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}
app/build.gradle.kts
dependencies {
    implementation("io.github.tranvanloccntt123:shield:0.1.0")
}

Maven POM 已声明 runtime dependency，因此 app 不需要重复声明。

配置 certificate​

ShieldConfig 要求 package ID 和至少一个小写 64 字符 SHA-256 hex digest：

private const val RELEASE_CERT_SHA256 = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"

private fun shieldConfig() = ShieldConfig(
    expectedPackage = BuildConfig.APPLICATION_ID,
    signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
)

将示例值替换为签名 APK 的 certificate digest：

apksigner verify --print-certs app-release.apk

将 digest 转为 lowercase 并删除 :。signing-key rotation 期间加入新 digest；APK 的所有 current signer 都必须在 allowlist 中，旧 signing history 不会自动接受。

选择 detector​

val emulator = TeiShield.check(applicationContext, ShieldCheck.EMULATOR)

val assessment = TeiShield.assess(
    applicationContext,
    AssessmentOptions(
        checks = setOf(ShieldCheck.EMULATOR, ShieldCheck.SDK_TEXT_INTEGRITY),
    ),
)

EMULATOR 只读取 Android build properties，不调用 native assessment、PackageManager、sensor 或 battery receiver。选择 APP_IDENTITY 时必须提供 AppIdentityConfig，否则 detector 运行前会抛出 IllegalArgumentException。

val options = AssessmentOptions(
    checks = setOf(ShieldCheck.APP_IDENTITY, ShieldCheck.EMULATOR),
    appIdentity = AppIdentityConfig(
        expectedPackage = BuildConfig.APPLICATION_ID,
        signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
    ),
)
val shield = TeiShield.initialize(
    applicationContext,
    options,
    ShieldRunPolicy(assessOnInitialize = false, reassessOnForeground = false),
)

shield.assess() 使用已保存 selection；shield.assess(options) 单次使用另一 selection，不改变 default。Assessment 完成前 configurable instance 的 lastAssessment == null。

每个 process 初始化一个 instance​

将 instance 放在 Application 中，不要放在每个 Activity/Fragment 中。Legacy initialize(config:) 会执行初始 assessment 并注册 foreground 监听。

ShieldApplication.kt
class ShieldApplication : Application() {
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.Default)

    val shield: Deferred<TeiShield> = scope.async(start = CoroutineStart.LAZY) {
        TeiShield.initialize(
            context = this@ShieldApplication,
            config = shieldConfig(),
        )
    }

    private fun shieldConfig() = ShieldConfig(
        expectedPackage = BuildConfig.APPLICATION_ID,
        signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
    )
}

在 manifest 中声明 Application：

AndroidManifest.xml
<application
    android:name=".ShieldApplication"
    ... />

读取 assessment​

MainActivity.kt
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        lifecycleScope.launch {
            val sdk = (application as ShieldApplication).shield.await()
            val assessment = sdk.assess()

            assessment.signals.forEach { signal ->
                Log.i("TEIShield", "${signal.code}: ${signal.status}")
            }
        }
    }
}

assess() 已在 background dispatcher 上运行，不需要再包裹 Dispatchers.IO。UI 通过 lifecycleScope 在 main thread 接收结果。

Lifecycle 和关闭 SDK​

TeiShield.initialize(config:) 注册 ProcessLifecycleOwner，当 process 回到 foreground 时调用 assess()。可配置 API 只有在 ShieldRunPolicy(reassessOnForeground = true) 时启用此行为。

当 process owner 结束或 app 主动丢弃 SDK session 时调用 close()。如果 activity 只是因旋转重建，不要在 Activity.onDestroy() 中调用 close()。

解释 Android signal​

常见 signal 包括 debugger、injectedImages、systemWritableMount、privilegedFiles、libcPointer、sdkTextIntegrity、emulator、missingMotionSensors、batteryUnavailable、appIdentity 和 storeAttestation。

  • package ID 正确且所有 current signer 匹配 allowlist 时，appIdentity 为 notDetected。
  • emulator 上可能出现 emulator: detected，这不是 root/jailbreak 证据。
  • 当前 public API 中 storeAttestation 为 unsupported，不要改成 notDetected。
  • error 和 unsupported 应走 fallback/step-up，不应当作 pass。

不要因为单个 heuristic signal 锁定用户，应结合多个 signal 与 risk engine，并对敏感操作要求额外验证。

R8/ProGuard 和 release​

AAR 附带保留 dev.tei.shield.NativeBridge 的 consumer rule。启用 R8 时不要修改 package/class 或移除 rule。发布前：使用真实 signing key 构建 release、检查 APK/AAB ABI 和 signer digest、在 emulator 及至少一台真实设备上运行 assessment，并在 redacted telemetry 中将 error/unsupported 与 notDetected 分开。

Local SDK 不替代 Play Integrity。若 server 需要 store evidence，请按 TEI1 wire protocol 和 Trust model 实现 server flow；0.1.0 尚未在 TeiShield 暴露创建 proof 的 API。
