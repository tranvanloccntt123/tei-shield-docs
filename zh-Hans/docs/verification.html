Runtime note​

初次 iOS Simulator test-host launch 在打开 dependency 时卡在 dyld，尚未执行 application code。将 derived product 重新构建到 /tmp/tei-shield-ios-tests 后解决。Workspace 位于 external volume；本机只需改变该路径。Runtime test 确认运行中的 framework 返回 sdkTextIntegrity: notDetected 和 emulator: detected。

Remaining device acceptance​

以下检查需要 developer configuration 和 physical device，尚未宣称通过：

  • 通过 Google Play test track 安装实际 Android package，配置 Cloud project、Application Default Credentials 和 signing digest，然后运行 live Play Integrity enrollment/protected request。
  • 为实际 Apple App ID 启用 App Attest，配置 App ID prefix 和 Bundle ID，并在支持的 iPhone 上分别测试 development/production distribution。
  • 验证 clean-device false positive、rooted/jailbroken lab device、real debugger attachment、injected instrumentation 和 patched SDK text；分开保存 negative 与 unsupported result。
  • 在实际 package 上测试 Android signing-key rotation、reinstall、restored backup、missing/invalidated key、lost enrollment response 和 explicit reset/re-enrollment。
  • 在 application networking layer 测试 offline/provider outage、request reorder、session rotation 和 response loss。
  • 在最老的 supported device 上测量 p50/p95 assessment/signing time、CPU、memory 和 foreground transition。Device crypto protection level 与 attestation latency 必须实测，不能从 emulator 推断。

Reproduction​

使用 README 中的命令。iOS framework runtime verification：

xcodebuild -project ios/TEIShield.xcodeproj -scheme TEIShieldSample \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath /tmp/tei-shield-ios-tests \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- test

CI 包含 C++、Kotlin、JNI、Swift、framework 和 packaging jobs。Workflow 已编写，但本 session 尚未在 GitHub 上运行。
