TEI Shield 통합

TEI Shield는 local-only 위험 평가 SDK입니다. 0.1.0에서 SDK는 backend를 호출하지 않고 계정을 요구하지 않으며 Play Integrity/App Attest proof를 자동으로 만들지 않습니다. 호스트 앱이 기기 local signal을 받고 자체 policy를 결정합니다.

통합 경로 선택​

앱추가할 artifact앱 계층 API
Android nativeMaven Central io.github.tranvanlocntt123:shield:0.1.0Kotlin TeiShield
iOS nativeBinary Swift Package tei-shield-iosSwift TeiShield
React Native / Exponpm package @teiresource/shield-expoTypeScript/JavaScript

자세한 문서: Android native, iOS native, React Native, Flutter.

공통 흐름​

  1. 플랫폼에 맞는 artifact를 추가하고 최소 SDK(Android API 26 또는 iOS 15)를 확인합니다.
  2. 일회성 check에는 check() 또는 assess(options:)를 직접 호출합니다. instance나 observer를 만들지 않습니다.
  3. 오래 사용할 때는 process당 하나의 instance만 초기화합니다. 화면이나 render마다 새 instance를 만들지 않습니다.
  4. legacy initialize(config:)는 즉시 assessment하고 foreground에서 다시 실행합니다. configurable API는 ShieldRunPolicy의 flag가 켜진 경우에만 자동 실행합니다.
  5. Assessment를 앱 policy에 연결합니다. unsupported나 error를 trusted device로 취급하지 마세요.
일회성:  check() / assess(options) ──> Assessment ──> App policy

재사용:  initialize(options, runPolicy)
                         │
                  필요 시, 초기화 시, foreground에서 assess()
                         │
                         └───────────────> Assessment ──> App policy

Detector 선택과 실행 시점​

emulator만 검사할 때는 package ID, certificate, native assessment, lifecycle observer가 필요하지 않습니다.

val emulator = TeiShield.check(applicationContext, ShieldCheck.EMULATOR)
let emulator = await TeiShield.check(.emulator)

여러 detector에는 AssessmentOptions(checks: ...)를 사용합니다. Android에서는 목록에 APP_IDENTITY가 있을 때만 AppIdentityConfig를 추가합니다. 빈 목록은 빈 assessment를 반환합니다.

React Native과 Flutter는 Signal code를 bridge로 전달합니다. 앱 고유 detector는 이 API 외부이며 반환 signal과 자체 policy를 조합할 수 있습니다.

결과 schema​

{
  "schemaVersion": 1,
  "signals": [
    { "code": "sdkTextIntegrity", "status": "notDetected", "confidence": "high" },
    { "code": "emulator", "status": "detected", "confidence": "high" }
  ],
  "durationMs": 1.4
}

detected는 detector가 해당 indicator를 관찰했다는 뜻일 뿐입니다. notDetected는 기기가 clean하다는 증명이 아닙니다. 단일 detector만으로 계정을 잠그거나 사용자를 거부하지 마세요.

error / unsupported  -> 상태를 기록하고 fallback 또는 step-up 사용
detected             -> 민감한 작업에 추가 검증 요구
notDetected          -> 일반 business policy 계속

SDK가 하지 않는 일​

  • telemetry, evidence, token, 기기 데이터를 앱 외부로 보내지 않습니다.
  • 사용자를 인증하거나 server API 권한을 부여하지 않습니다.
  • 현재 버전에는 enrollment, assertion 생성, HTTP request signing API가 없습니다.
  • local signal 하나만으로 secure hardware를 주장하지 않습니다.

Server 작업 보호는 TEI1 wire protocol을 참고하세요. Server는 session, challenge, signature/evidence, transaction을 독립적으로 확인해야 하며 local Assessment를 trust anchor로 사용하면 안 됩니다.

통합 보안​

  • raw evidence, private key, challenge, 민감한 body를 log에 기록하지 않습니다.
  • proof request의 body bytes와 raw path/query를 유지하고 JSON을 다시 serialize하지 않습니다.
  • Android allowlist에는 package ID와 모든 current signer의 SHA-256 digest를 넣습니다.
  • iOS release에는 artifacts/ios/의 binary package를 사용합니다. source Swift Package는 post-link sealing을 하지 않아 sdkTextIntegrity: unsupported가 될 수 있습니다.
  • simulator/emulator 결과와 실제 기기 결과를 구분합니다.

Detector 범위는 Trust model, release 검증은 Verification record을 참고하세요.
