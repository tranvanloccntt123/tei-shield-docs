Protocol helpers and C ABI

These utilities exist in source, but do not implement enrollment, evidence generation, request signing, transport, or server verification. Most applications need only the assessment API. Expo/Flutter do not expose the protocol helpers or C ABI.

Native protocol helpers​

ProtectedRequest(method, target, body) in Kotlin and try ProtectedRequest(method:target:body:) in Swift validate a nonempty uppercase ASCII-letter method and a printable ASCII target beginning with /, but not //, containing no # or spaces. The target is the raw path and query, not a full URL. Body is ByteArray / Data; no JSON parse or reserialization occurs. Kotlin invalid construction throws IllegalArgumentException; Swift throws ShieldError.invalidRequest.

import Foundation
import TEIShield

let request = try ProtectedRequest(
    method: "POST", target: "/v1/example?b=2&a=1",
    body: Data("{\"amount\":10}".utf8)
)
let bytes = ShieldProtocol.requestBytes(
    request, audience: "example-app",
    timestamp: "1788600000000", challenge: "example-only", keyId: "example-only"
)
// Framing only: these placeholder values are not a valid proof.

The helpers do not validate that audience/key ID/challenge/timestamp came from a trusted server. Kotlin encode caps each UTF-8 field at 1,048,576 bytes but has no field-count guard. Swift uses preconditions for at most 64 fields and 1,048,576 bytes per field; a violated precondition traps rather than returning an error. Validate untrusted sizes before calling. The lower-level C encoder has different limits below.

Transport models are not service APIs​

Challenge has value, expiresAt, purpose. Kotlin validate(expected) checks purpose, a 43-character Base64url alphabet, and future ISO-8601 expiry. Swift has a public initializer and Codable fields, but validate is internal; it is not a public API for app callers.

Enrollment carries platform, challenge, keyId, publicKey, evidence, signature. Kotlin defaults platform to android and exposes json(): JSONObject. RequestProof carries platform, challenge, keyId, timestamp, evidence, signature; Kotlin header() and Swift try header() encode JSON as padded standard Base64, not Base64url. Encoding is not signing or proof verification.

Swift models are Codable; Enrollment, RequestProof, Signal, and Assessment do not declare public memberwise initializers in this source. Do not assume an external app can construct them with synthesized memberwise syntax. Decode transport models where appropriate; assessment results come from the SDK.

Swift's public ShieldError cases are unsupported, invalidRequest, expiredChallenge, missingKey, enrollmentAlreadyAttested, keychain(Int32), and invalidResponse. Their existence does not mean assessment exposes key enrollment or attestation APIs. KeyStorage is internal.

The routes and verification behavior in TEI1 wire protocol describe a server contract to implement separately. This repository has no runnable server/ directory, provider verifier, or HTTP client for those routes.

C ABI for native integrators​

Declared in core/include/tei_shield.h. Input strings are UTF-8 bytes. Caller owns output memory; no function allocates a returned buffer for the caller to free.

FunctionContract
tei_encode(fields, sizes, count, output, capacity)Returns required bytes; null/short output performs no write. Invalid pointers/lengths, more than 64 fields, field over UINT32_MAX, or overflow returns 0. Empty field list encodes four bytes TEI1
tei_sha256(bytes, size, output)Writes exactly 32 digest bytes into caller-provided storage
tei_assess(output, capacity)Runs all seven native checks and returns JSON signal array, not the platform Assessment object
tei_assess_selected(mask, output, capacity)Runs selected native checks only; returns required bytes including NUL; writes only if capacity is sufficient. Unknown bits return 0; zero mask serializes []
tei_tracer_present(status)Parses text containing TracerPid:; returns -1 malformed/missing/null, 0 no tracer, 1 tracer present

Native flags are TEI_CHECK_DEBUGGER, TEI_CHECK_INJECTED_IMAGES, TEI_CHECK_SYSTEM_WRITABLE_MOUNT, TEI_CHECK_PRIVILEGED_FILES, TEI_CHECK_LIBC_POINTER, TEI_CHECK_SDK_TEXT_INTEGRITY, TEI_CHECK_TOOL_PORT (bits 0–6); TEI_CHECK_ALL_NATIVE combines them. The other five platform checks have no C flags.

#include "tei_shield.h"
#include <stdexcept>
#include <string>
#include <vector>

std::string assessSdkText() {
    // Every assessment call actually runs checks, even when output is null.
    // Retry sizing if a later snapshot needs a larger JSON buffer.
    std::vector<char> output(8192);
    for (int attempt = 0; attempt < 3; ++attempt) {
        const size_t needed = tei_assess_selected(
            TEI_CHECK_SDK_TEXT_INTEGRITY, output.data(), output.size());
        if (needed == 0) throw std::runtime_error("Invalid native check mask");
        if (needed <= output.size()) return std::string(output.data(), needed - 1);
        output.resize(needed);
    }
    throw std::runtime_error("Native assessment size kept changing");
}

Do not parse a too-small/unwritten buffer, and do not treat 0 as a successful empty assessment. Use tei_encode's two-pass sizing for byte framing; for assessment, two calls can observe different states. Golden encoding vectors live in protocol/vectors.json with a Swift fixture copy under ios/Tests/TEIShieldTests/vectors.json.
