React Native / Expo 통합

@teiresource/shield-expo 모듈은 npm registry에서 직접 배포됩니다. Android는 Maven Central에서 SDK io.github.tranvanloccntt123:shield:0.1.0을 resolve하고, Swift bridge는 package에 포함된 XCFramework를 사용합니다. TypeScript가 detector 선택, client, lifecycle을 관리합니다.

이 모듈은 Expo Modules API를 사용하며 Expo Modules가 설치된 Expo 또는 React Native 프로젝트에서 사용할 수 있습니다. development/native build가 필요합니다. 일반 Expo Go에는 TEI Shield native binary가 포함되어 있지 않습니다. 기준 예제는 Expo SDK 55, React Native 0.83, React 19.2를 사용하며 Android API 26+ 및 iOS 15.1+가 필요합니다.

Expo 앱에 설치​

npx expo install @teiresource/shield-expo
npx expo install expo-dev-client

app.json에 config plugin을 추가합니다.

app.json
{
  "expo": {
    "plugins": ["@teiresource/shield-expo"]
  }
}

native project를 생성하고 development build를 실행합니다.

npx expo prebuild
npx expo run:android
# 또는:
npx expo run:ios

AAR는 arm64-v8a와 x86_64를 지원합니다. release 전에 Gradle properties에 reactNativeArchitectures=arm64-v8a,x86_64를 설정하거나 expo-build-properties의 android.buildArchs: ['arm64-v8a', 'x86_64']를 사용합니다. Autolinking이 Kotlin/Swift 모듈을 자동으로 등록합니다. EAS Build에서는 Gradle이 Maven Central에서 SDK를 resolve하고 iOS XCFramework는 npm package 안에 유지됩니다. package를 설치하거나 업그레이드한 뒤 npx expo prebuild를 다시 실행하세요.

기존 native project의 React Native​

npm install @teiresource/shield-expo
npx pod-install

아직 Expo Modules를 사용하지 않는 프로젝트라면 Expo Modules를 설치하세요. Android minSdk는 >= 26, iOS target은 >= 15.1을 유지합니다. ReactPackage를 수동으로 등록할 필요가 없습니다. Android host의 dependencyResolutionManagement.repositories에는 google()과 mavenCentral()이 필요합니다.

Hermes와 R8을 사용한 release 보안​

React Native/Expo release build에는 다음 두 보호 계층을 활성화해야 합니다.

  • Hermes는 JavaScript/TypeScript를 bytecode로 컴파일하여 읽기 쉬운 source를 APK에 그대로 포함하지 않습니다.
  • R8은 native Java/Kotlin 코드를 shrink, 최적화, obfuscate하고 class, method, field를 a, b, c 같은 짧은 이름으로 변경합니다.

R8이 reverse engineering을 불가능하게 만들지는 않지만 APK 분석을 훨씬 어렵게 합니다. 이는 release artifact를 보호하는 기능이며 server 인증, API 제어, secret 하드코딩 방지를 대신하지 않습니다.

Expo에서 R8 구성​

npx expo install expo-build-properties

app.json 또는 app.config.js에 추가합니다.

app.json
{
  "expo": {
    "plugins": [
      "@teiresource/shield-expo",
      [
        "expo-build-properties",
        {
          "android": {
            "enableMinifyInReleaseBuilds": true,
            "enableShrinkResourcesInReleaseBuilds": true
          }
        }
      ]
    ]
  }
}

enableMinifyInReleaseBuilds는 release build에서 R8을 활성화합니다. enableShrinkResourcesInReleaseBuilds는 사용하지 않는 resource를 제거하여 APK 크기를 줄입니다. 최신 Expo SDK에서는 오래된 enableProguardInReleaseBuilds 대신 이 property를 사용하세요.

Build 및 검증​

이전 설정으로 생성된 android/ 디렉터리가 있다면 release build 전에 다시 생성합니다.

npx expo prebuild
npx expo run:android --variant release

npx expo prebuild로 plugin 설정을 적용하고 diff를 확인합니다. Native project가 설정으로 완전히 재생성되고 수동 변경이 저장된 경우에만 npx expo prebuild --clean을 사용합니다. Clean은 native 디렉터리를 교체합니다. 수동 관리 project에서는 해당 Gradle 설정을 직접 수정합니다.

# R8이 실행되면 mapping file이 존재해야 합니다
ls -la android/app/build/outputs/mapping/release/mapping.txt

# minifyEnabled true가 표시되어야 합니다
grep "minifyEnabled" android/app/build.gradle

나중에 crash stack trace를 디코딩할 수 있도록 mapping.txt를 release artifact와 함께 안전하게 보관합니다. JADX로 APK를 추가 확인할 수도 있습니다.

jadx android/app/build/outputs/apk/release/app-release.apk -d /tmp/decompiled
ls /tmp/decompiled/sources/

필수 release 테스트​

R8은 reflection으로 접근하는 class를 제거할 수 있습니다. release build를 실제 기기에 설치하고 module initialization, autolinking, assessment 및 다른 native library를 테스트하세요. debug에서는 동작하지만 release에서 crash가 발생하면 로그를 확인합니다.

adb logcat | grep -i "error\|crash\|exception"

문제가 발생한 library에 필요한 keep rule을 추가하고 TEI Shield의 consumer rule도 유지하세요. 전체 release checklist는검증 가이드를 참고하세요.

원문 참고: Enabling Code Obfuscation in Expo React Native: R8 Shrinking & Obfuscation.

일회성 검사​

import {assess, check} from '@teiresource/shield-expo';

const emulator = await check('emulator');
const result = await assess({checks: ['emulator', 'sdkTextIntegrity']});
const empty = await assess(); // signals: []; observer를 초기화하지 않음

SHIELD_CHECKS에는 12개의 public code가 있습니다. 결과에는 선택한 detector만 포함되며 잘못된 code는 TypeScript와 native에서 모두 거부됩니다.

클라이언트 앱에서 구성​

import {createClient, SHIELD_CHECKS} from '@teiresource/shield-expo';

const identity = {
  expectedPackage: 'com.company.mobile',
  signingCertificateSha256: [releaseCertificateSha256, nextCertificateSha256],
};

const client = await createClient({
  options: {
    checks: ['appIdentity', 'emulator', 'sdkTextIntegrity'],
    appIdentity: identity,
  },
  runPolicy: {assessOnInitialize: false, reassessOnForeground: true},
  onAssessment: assessment => appRiskPolicy.consume(assessment),
  onError: error => reportAssessmentFailure(error),
});

const configured = await client.assess();
const once = await client.assess({checks: ['debugger']});
const all = await client.assess({checks: SHIELD_CHECKS, appIdentity: identity});
client.close();

Android에서 appIdentity를 선택하면 비어 있지 않은 expectedPackage와 소문자 64자 SHA-256 hex digest가 하나 이상 필요합니다. 모든 current signer는 allowlist에 있어야 합니다. iOS의 appIdentity는 unsupported를 반환합니다. unsupported/error를 notDetected로 바꾸지 말고 앱에서 fallback, step-up, telemetry policy를 결정하세요.

Schema 및 policy​

type Assessment = {
  schemaVersion: number;
  signals: {code: string; status: 'detected' | 'notDetected' | 'unsupported' | 'error'; confidence: string}[];
  durationMs: number;
};

Bridge는 status와 confidence를 보존하지만 앱을 잠그거나 process를 종료하거나 UI를 표시하거나 network request를 보내지 않습니다. detector, confidence, context를 바탕으로 policy를 결정하는 것은 클라이언트 앱의 책임입니다. iOS는 appIdentity, storeAttestation, missingMotionSensors, batteryUnavailable를 지원하지 않습니다.

Example 실행 및 테스트​

cd packages/tei-shield-expo
npm ci
npm run build
npm test
cd example
npm install
npx expo prebuild
npx expo run:android
# 또는 npx expo run:ios

TypeScript test는 fake runtime으로 contract와 lifecycle을 확인합니다. development build, release/R8, foreground 동작, 실제 signing certificate는검증 가이드에 따라 실제 기기에서도 확인하세요.
