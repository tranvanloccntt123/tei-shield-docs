TEI1 wire protocol

Transport는 HTTPS를 사용합니다. Evidence를 URL query string에 넣지 않습니다. sample route는 최대 65,536 bytes body를 받으며 모든 route에 session authentication이 필요합니다. Attestation은 사람 사용자를 인증하지 않습니다.

Canonical bytes​

TEI1(4 ASCII bytes) 뒤에 각 field를 uint32 big-endian UTF-8 byte length || UTF-8 bytes로 고정 순서에 따라 붙입니다. delimiter escaping, Unicode normalization, URL decoding, query sorting, JSON reserialization을 하지 않습니다. Body SHA-256은 lowercase hexadecimal, timestamp는 13자리 Unix milliseconds입니다. Golden vector에는 multibyte UTF-8, NUL, empty field가 포함됩니다.

Request fields:

request, METHOD, audience, raw-path-and-query, sha256(original-body-bytes), timestamp, challenge, keyId

Enrollment fields:

enroll, platform, audience, challenge, keyId, publicKey

Android publicKey는 P-256 canonical padded Base64 SPKI DER입니다. Android key ID는 해당 DER의 SHA-256 unpadded Base64url입니다. iOS key ID는 App Attest의 exact padded Base64 string이고 enrollment publicKey는 비어 있습니다. Server가 attestation certificate에서 파생하기 때문입니다. Session binding은 caller-controlled claim이 아니라 저장된 challenge로 제공합니다.

Android는 canonical bytes를 SHA256withECDSA로 서명하고 DER signature를 padded Base64로 인코딩합니다. Enrollment와 protected request 모두 key possession proof가 필요합니다. Play Integrity requestHash는 같은 canonical bytes의 SHA-256 unpadded Base64url입니다. iOS는 canonical bytes의 SHA-256을 clientDataHash로 App Attest에 전달합니다.

Endpoints​

모든 route에는 앱 session authorization이 필요합니다. Challenge/enrollment/revocation JSON body는 UTF-8이고 protected request body는 Content-Type이 JSON이어도 opaque bytes입니다.

EndpointInputOutput
POST /v1/challenges{"purpose":"enroll"} 또는 {"purpose":"request"}{value, expiresAt, purpose}
POST /v1/devices{platform, challenge, keyId, publicKey, evidence, signature}{keyId}
POST /v1/sensitiveOriginal body와 X-TEI-Proof header{id, status:"accepted"}
POST /v1/devices/revoke{keyId}{revoked:true}

X-TEI-Proof는 UTF-8 JSON의 padded Base64입니다.

{
  "platform": "android",
  "challenge": "<server-issued value>",
  "keyId": "<registered key>",
  "timestamp": "1788600000000",
  "evidence": "<Play Integrity token or base64 App Attest assertion>",
  "signature": "<base64 Android DER signature; empty for iOS>"
}

Enrollment evidence는 Play Integrity token 또는 base64 App Attest attestation입니다. iOS enrollment signature는 비어 있습니다. Proof JSON field 순서는 중요하지 않으며 실제 HTTP method, raw URL, server audience, body bytes와 함께 canonical bytes를 재구성합니다.

Challenge는 padding 없는 Base64url 32 random bytes이며 120초 후 만료되고 user ID, session ID, purpose에 bind됩니다. Consumption, device counter update, sample business operation은 하나의 PostgreSQL transaction에서 commit됩니다. 검증 실패는 모두 rollback합니다. Revoked key는 다시 enrollment해도 활성화되지 않습니다.

Sensitive endpoint는 sample operation record만 기록하고 payment는 처리하지 않습니다. 실제 business effect는 같은 transaction 안에 두고, 외부 side effect에는 transactional outbox와 downstream idempotency를 사용합니다.

Failure와 retry​

Error는 {error, retryable}입니다. Auth 누락 401, malformed input 400, verification 거부 403, duplicate registration 409, rate limit 429, 일시적 provider failure 503을 반환합니다. Provider exception text, body, token, signature는 반환하거나 log하지 않습니다.

Network가 불확실하면 새 challenge를 받아 proof를 다시 생성합니다. Google token이 이미 decode되었거나 iOS counter가 증가했을 수 있으므로 consumed token을 무한 재시도하지 않습니다. Upstream header limit을 설정하고 exact path/query bytes를 보존하며 redirect를 끄고 signed body를 변환하지 않습니다. iOS request는 key별로 serial하게 보내고, counter가 앞선 assertion을 거부하면 새 challenge로 retry합니다.
