50회의 debug-core assessment host-only timing sample은 median 0.699 ms, p95 0.946 ms였습니다. 이는 mobile performance claim이 아닙니다. Detector coverage, loaded image, hardware, build mode가 다릅니다.

Test fixture는 이 project의 live provider account를 사용하지 않습니다.

Runtime note​

초기 iOS Simulator test-host launch가 dependency를 여는 dyld에서 멈추어 application code 전에 종료되었습니다. derived product를 /tmp/tei-shield-ios-tests로 다시 빌드하여 해결했습니다. Runtime test는 framework에서 sdkTextIntegrity: notDetected와 emulator: detected를 확인합니다.

Remaining device acceptance​

다음은 developer configuration과 physical device가 필요하며 아직 passed로 주장하지 않습니다.

  • Google Play test track, Cloud project, Application Default Credentials, signing digest를 설정하고 live Play Integrity enrollment/protected request를 실행합니다.
  • 실제 Apple App ID에서 App Attest를 활성화하고 App ID prefix와 Bundle ID를 설정하여 development/production distribution을 지원 iPhone에서 각각 테스트합니다.
  • Clean-device false positive, rooted/jailbroken lab device, real debugger, injected instrumentation, patched SDK text를 검증하고 negative와 unsupported를 분리해 저장합니다.
  • 실제 package에서 signing-key rotation, reinstall, restored backup, missing/invalidated key, lost enrollment response, reset/re-enrollment을 테스트합니다.
  • Networking layer에서 offline/provider outage, request reorder, session rotation, response loss를 테스트합니다.
  • 가장 오래된 supported device에서 p50/p95 assessment/signing time, CPU, memory, foreground transition을 측정합니다. Crypto protection level과 attestation latency는 emulator에서 추론하지 말고 측정해야 합니다.

Reproduction​

README 명령을 사용합니다. iOS framework runtime verification:

xcodebuild -project ios/TEIShield.xcodeproj -scheme TEIShieldSample \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath /tmp/tei-shield-ios-tests \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- test

CI에는 PostgreSQL, C++, Kotlin, JNI, Swift, framework, packaging job이 포함됩니다. Workflow는 작성되었지만 이 session에서는 GitHub에서 실행하지 않았습니다.
