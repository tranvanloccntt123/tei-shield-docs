TEI1 wire protocol

実装範囲

この repository は local assessment と byte framing helper を提供します。実行可能な server、attestation provider 連携、enrollment/request signing API は含まれません。以下の endpoint、制限、検証、retry は別途実装する契約案であり、SDK が提供するサービスではありません。

Transport は HTTPS を使用します。Evidence を URL query string に入れません。Sample route の body 上限は 65,536 bytes です。全 route に session authentication が必要で、attestation は人間の user を認証しません。

Canonical bytes​

TEI1（4 ASCII bytes）の後に各 field を uint32 big-endian UTF-8 byte length || UTF-8 bytes として並べます。順序は固定です。delimiter escaping、Unicode normalization、URL decoding、query sorting、JSON reserialization は行いません。Body SHA-256 は lowercase hexadecimal、timestamp は 13 桁 Unix milliseconds です。Golden vector には multibyte UTF-8、NUL、empty field が含まれます。

Request fields:

request, METHOD, audience, raw-path-and-query, sha256(original-body-bytes), timestamp, challenge, keyId

Enrollment fields:

enroll, platform, audience, challenge, keyId, publicKey

Android publicKey は P-256 の canonical padded Base64 SPKI DER。Android key ID はその DER の SHA-256 unpadded Base64url。iOS key ID は App Attest の exact padded Base64 string で、enrollment publicKey は空です。Server が attestation certificate から導出するためです。Session binding は caller-controlled claim ではなく保存済み challenge で行います。

Android は canonical bytes を SHA256withECDSA で署名し、DER signature を padded Base64 にします。Enrollment と protected request の両方で key possession proof が必要です。Play Integrity requestHash は同じ canonical bytes の SHA-256 unpadded Base64url。iOS は canonical bytes の SHA-256 を clientDataHash として App Attest に渡します。Server verification は hex 表現ではなく元の canonical bytes を受け取ります。

Endpoints​

全 route に application session authorization が必要です。Challenge/enrollment/revocation の JSON body は UTF-8。Protected request body は Content-Type が JSON でも opaque bytes です。

EndpointInputOutput
POST /v1/challenges{"purpose":"enroll"} または {"purpose":"request"}{value, expiresAt, purpose}
POST /v1/devices{platform, challenge, keyId, publicKey, evidence, signature}{keyId}
POST /v1/sensitiveOriginal body と X-TEI-Proof header{id, status:"accepted"}
POST /v1/devices/revoke{keyId}{revoked:true}

X-TEI-Proof は UTF-8 JSON の padded Base64 です。

{
  "platform": "android",
  "challenge": "<server-issued value>",
  "keyId": "<registered key>",
  "timestamp": "1788600000000",
  "evidence": "<Play Integrity token or base64 App Attest assertion>",
  "signature": "<base64 Android DER signature; empty for iOS>"
}

Enrollment evidence は Play Integrity token または base64 App Attest attestation。iOS enrollment signature は空です。Proof JSON の順序は関係なく、実際の HTTP method、raw URL、server audience、body bytes と組み合わせて canonical bytes を再構成します。

Challenge は padding なし Base64url の 32 random bytes で、120 秒後に expire し user ID、session ID、purpose に bind されます。Consumption、device counter update、sample business operation は 1 つの PostgreSQL transaction で commit されます。検証失敗は 3 つすべてを rollback。Provider verification 後にも expiry を再確認し、duplicate enrollment は既存/ revoked key を置き換えません。

Sensitive endpoint は sample operation record を書くだけで payment は処理しません。実際の database business effect は同じ transaction に置きます。外部 side effect には transactional outbox と downstream idempotency を使用し、transaction 後の action を exactly once と仮定しないでください。

Failure と retry​

Error は {error, retryable}。Authentication 不足は 401、malformed input は 400、verification reject は 403、duplicate registration は 409、rate limit は 429、temporary provider failure は 503。Provider の例外 text、body、token、signature は返さず log しません。

Network が不確かな場合は新しい challenge を取得して proof を生成し直します。Google token は decode 済み、iOS counter は進んでいる可能性があります。Consumed token を無限 retry しません。

SDK は local signal のみを返します。Backend 連携には認証、evidence 生成と独立した検証、challenge 保存、replay 防止、業務 policy の別途実装が必要です。この repository に server/ や provider test suite はありません。Wire protocol は契約案、protocol helper は実装済み utility の説明です。storeAttestation を選択しても provider は呼ばれません。
