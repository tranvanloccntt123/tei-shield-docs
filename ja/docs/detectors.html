Detector catalog

Every requested detector produces a Signal with code, status, and confidence. Unselected detectors do not appear. Match by code, not array position: results follow implementation order, not caller order. These behaviors come from core/src/detectors.cpp and the native Kotlin/Swift assessment implementations.

Status and confidence​

ValueMeaningApplication handling
detectedThe detector observed its indicatorEvaluate that indicator in context
notDetectedThe detector did not observe its indicatorDoes not prove the environment is uncompromised
unsupportedThis implementation/build does not provide the checkTrack as unavailable coverage
errorThe check could not obtain/interpret its dataTrack as failed coverage; investigate the build/device

Confidence is a fixed label for the detector, not a probability, severity, or aggregate score. It stays present on unsupported and error results. Android emulator confidence is medium; iOS emulator confidence is high.

Android identity configuration​

expectedPackage must be nonblank; signingCertificateSha256 must contain at least one lowercase 64-character hexadecimal digest. The SDK does not lowercase, trim, or remove colons for you. Use the app's expected distribution identity, not a digest learned from an untrusted runtime and automatically accepted.

apksigner verify --print-certs app-release.apk

Take the signer certificate SHA-256 digest, remove separators if present, and lowercase it. Use the certificate for the actual installed distribution; debug, locally signed release, and store-delivered packages can differ. Keep allowlists per build environment. During planned rotation, include the intended allowed certificates; matching one certificate is insufficient if another current signer is not allowlisted. API 28+ uses apkContentsSigners; it does not compare the whole signing history.

Only Android selections containing appIdentity require this object. Swift has no AppIdentityConfig. Expo/Flutter accept it for shared cross-platform configuration; if supplied, the bridges validate its shape on iOS too, even though iOS returns unsupported for identity.
