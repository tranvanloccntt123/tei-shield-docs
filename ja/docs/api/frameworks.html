Expo and Flutter API

This reference covers wrapper source version 0.1.9. Use the Expo guide or Flutter guide for native installation. Both wrappers support Android/iOS and call native static assessment; they do not create a native lifecycle instance.

Clients copy/deduplicate selections and certificates; Dart collections are immutable and Expo snapshots are frozen. The one-off override replaces the full options object, including identity, for that call. It does not alter defaults. lastAssessment can therefore describe a different selection than the defaults.

Expo exports and signatures​

Import from @teiresource/shield-expo:

assess(options?: AssessmentOptions): Promise<Assessment>
check(check: ShieldCheck, appIdentity?: AppIdentityConfig): Promise<Signal>
createClient(config: ClientConfig): Promise<TeiShieldClient>

The signatures above are reference notation. assess() defaults to {checks: []}. check() returns the selected signal, not an assessment. Neither installs listeners or writes to a client's cache.

ClientConfig requires options, and accepts optional runPolicy, onAssessment(value: Assessment): void, and onError(error: unknown): void. assessOnInitialize waits for the first run before resolving createClient; onAssessment can run before the caller receives the client. Avoid callbacks that depend on the client variable already being assigned. Callbacks are synchronous notification hooks; the client does not await asynchronous callback work.

Client memberResultContract
client.assess(options?)Promise<Assessment>Stored defaults or one-call replacement
client.check(check)Promise<Signal>Single check with stored identity; also updates cache and emits a one-signal assessment callback
client.lastAssessmentAssessment | nullRead-only latest successful assessment
client.close()voidIdempotent; unsubscribe and mark closed; cache is retained

The exported class also exposes TeiShieldClient.initialize(runtime, config). runtime is an adapter with platform, assess(options), and subscribeForeground(callback) returning an unsubscribe function. It is useful for tests/custom hosts; normal apps use createClient, which supplies the React Native runtime and native module lookup.

Manual assessment failures reject their Promise; automatic failures go to onError. A synchronous exception thrown by onAssessment is reported to onError without rejecting an otherwise successful assessment. Exceptions from onError itself are swallowed so the queue remains usable. Always attach error handling to manual calls even when onError exists.

import {createClient} from '@teiresource/shield-expo';

const client = await createClient({
  options: {checks: ['emulator', 'sdkTextIntegrity']},
  runPolicy: {assessOnInitialize: true, reassessOnForeground: true},
  onAssessment: value => console.log(value.signals),
  onError: () => console.warn('Automatic assessment unavailable'),
});
try {
  const result = await client.assess();
  // Evaluate result.signals, including unsupported/error, using your app policy.
} catch {
  // Mark coverage unavailable in your app; do not treat the failure as a pass.
} finally {
  client.close(); // In a long-lived app, call this when the owning session ends.
}

Flutter constructors and methods​

Client memberResultContract
client.optionsAssessmentOptionsRead-only stored configuration
client.assess([override])Future<TeiShieldAssessment>Stored defaults or one-call replacement
client.check(check)Future<TeiShieldSignal>Uses stored identity; emits/cache stores the one-signal assessment
client.lastAssessmentTeiShieldAssessment?Null before success; retained after close
client.assessmentsStream<TeiShieldAssessment>Broadcast, does not replay; emits successful manual and automatic runs

AppIdentityConfig.toMap() and AssessmentOptions.toMap() provide native payloads. TeiShieldSignal.fromMap() and TeiShieldAssessment.fromMap() decode native maps; the latter converts numeric duration to double. These are strict decoders for the bridge schema, not validation tools for arbitrary server input. TeiShieldAssessment copies signals into an unmodifiable list.

final client = await TeiShieldClient.initialize(
  options: AssessmentOptions(checks: [ShieldCheck.emulator]),
  runPolicy: const ShieldRunPolicy(assessOnInitialize: true),
);
final initial = client.lastAssessment; // Stream cannot replay this initial value.
final subscription = client.assessments.listen(
  (value) { /* Update app state from value.signals. */ },
  onError: (Object error, StackTrace stack) { /* Mark automatic coverage unavailable. */ },
);
try {
  final result = await client.assess();
} catch (_) {
  // Manual failures arrive here, not in the stream error channel.
} finally {
  await subscription.cancel();
  await client.close();
}

Cancel owned subscriptions before awaiting close(); a paused listener can delay stream completion. Stream callbacks belong to the subscriber and are not SDK policy hooks.

Queue, foreground, and teardown​

Each client serializes its own requests. Repeated foreground events are coalesced while one automatic assessment is queued/running. Independent clients and static calls do not share this queue.

Expo observes background/inactive → active. Flutter observes a transition to resumed from a known state other than resumed or detached. Initial attachment alone does not count as a framework foreground transition. There is no timer or background service.

After close, new and queued requests fail. Native work already running can finish, but the framework client rejects its late result, suppresses callbacks/stream delivery, and does not update the cache. Close does not wait for or cancel that native work. Still handle outstanding manual Promises/Futures during teardown. Create a new client to change defaults or resume automatic work.
