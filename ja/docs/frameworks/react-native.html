React Native / Expo の統合

@teiresource/shield-expo モジュールは npm registry から直接配布されます。Android は Maven Central から SDK io.github.tranvanloccntt123:shield:0.1.0 を解決し、Swift bridge は package に含まれる XCFramework を使用します。detector の選択、client、ライフサイクルは TypeScript で管理します。

このモジュールは Expo Modules API を使用し、Expo Modules を導入した Expo または React Native プロジェクトで利用できます。development/native build が必要です。通常の Expo Go には TEI Shield の native binary は含まれません。基準例は Expo SDK 55、React Native 0.83、React 19.2 を使用し、Android API 26+ と iOS 15.1+ が必要です。

Expo アプリへのインストール​

npx expo install @teiresource/shield-expo
npx expo install expo-dev-client

app.json に config plugin を追加します。

app.json
{
  "expo": {
    "plugins": ["@teiresource/shield-expo"]
  }
}

native project を生成して development build を実行します。

npx expo prebuild
npx expo run:android
# または:
npx expo run:ios

AAR は arm64-v8a と x86_64 をサポートします。リリース前に Gradle properties へ reactNativeArchitectures=arm64-v8a,x86_64 を設定するか、expo-build-properties の android.buildArchs: ['arm64-v8a', 'x86_64'] を使用します。Autolinking が Kotlin/Swift モジュールを自動登録します。EAS Build では Gradle が Maven Central から SDK を解決し、iOS XCFramework は npm package 内に残ります。package のインストールや更新後は npx expo prebuild を再実行してください。

既存 native project の React Native​

npm install @teiresource/shield-expo
npx pod-install

Expo Modules をまだ導入していない場合はExpo Modules をインストールしてください。Android minSdk は >= 26、iOS target は >= 15.1 を維持します。ReactPackage を手動登録する必要はありません。Android host の dependencyResolutionManagement.repositories には google() と mavenCentral() が必要です。

Hermes と R8 によるリリース保護​

React Native/Expo の release build では、次の 2 層を有効にします。

  • Hermes は JavaScript/TypeScript を bytecode にコンパイルし、読みやすい source を APK にそのまま含めません。
  • R8 は native Java/Kotlin code を shrink、最適化、obfuscate し、class・method・field を a、b、c のような短い名前に変更します。

R8 は reverse engineering を不可能にはしませんが、APK の解析を大幅に難しくします。release artifact の保護であり、server 認証、API 制御、secret のハードコード回避の代わりではありません。

Expo の R8 設定​

npx expo install expo-build-properties

app.json または app.config.js に追加します。

app.json
{
  "expo": {
    "plugins": [
      "@teiresource/shield-expo",
      [
        "expo-build-properties",
        {
          "android": {
            "enableMinifyInReleaseBuilds": true,
            "enableShrinkResourcesInReleaseBuilds": true
          }
        }
      ]
    ]
  }
}

enableMinifyInReleaseBuilds は release build で R8 を有効にします。enableShrinkResourcesInReleaseBuilds は未使用 resource を削除して APK サイズを小さくします。現在の Expo SDK では、古い enableProguardInReleaseBuilds ではなくこれらの property を使用してください。

Build と検証​

古い設定から生成された android/ ディレクトリがある場合は、release build の前に再生成します。

npx expo prebuild
npx expo run:android --variant release

npx expo prebuild で plugin 設定を適用し diff を確認します。Native project が設定から完全に再現でき、手動変更が保存済みの場合のみ npx expo prebuild --clean を使用してください。Clean は native directory を置き換えます。手動管理の project では対応する Gradle 設定を直接編集します。

# R8 が実行されると mapping file が存在します
ls -la android/app/build/outputs/mapping/release/mapping.txt

# minifyEnabled true が表示される必要があります
grep "minifyEnabled" android/app/build.gradle

後で crash stack trace を復号できるよう、mapping.txt を release artifact と一緒に安全に保存します。JADX でも APK を確認できます。

jadx android/app/build/outputs/apk/release/app-release.apk -d /tmp/decompiled
ls /tmp/decompiled/sources/

必須の release テスト​

R8 は reflection で参照される class を削除することがあります。release build を実機にインストールし、module initialization、autolinking、assessment、その他の native library をテストしてください。debug では動くのに release で crash する場合はログを確認します。

adb logcat | grep -i "error\|crash\|exception"

問題の library に必要な keep rule を追加し、TEI Shield の consumer rule も保持してください。完全な release checklist は検証ガイドにあります。

原文：Enabling Code Obfuscation in Expo React Native: R8 Shrinking & Obfuscation。

1 回だけ実行するチェック​

import {assess, check} from '@teiresource/shield-expo';

const emulator = await check('emulator');
const result = await assess({checks: ['emulator', 'sdkTextIntegrity']});
const empty = await assess(); // signals: []; observer は初期化されません

SHIELD_CHECKS には 12 個の public code があります。結果には選択した detector だけが含まれ、無効な code は TypeScript と native の両方で拒否されます。

クライアントアプリからの設定​

import {createClient, SHIELD_CHECKS} from '@teiresource/shield-expo';

const identity = {
  expectedPackage: 'com.company.mobile',
  signingCertificateSha256: [releaseCertificateSha256, nextCertificateSha256],
};

const client = await createClient({
  options: {
    checks: ['appIdentity', 'emulator', 'sdkTextIntegrity'],
    appIdentity: identity,
  },
  runPolicy: {assessOnInitialize: false, reassessOnForeground: true},
  onAssessment: assessment => appRiskPolicy.consume(assessment),
  onError: error => reportAssessmentFailure(error),
});

const configured = await client.assess();
const once = await client.assess({checks: ['debugger']});
const all = await client.assess({checks: SHIELD_CHECKS, appIdentity: identity});
client.close();

Android で appIdentity を選択する場合、空でない expectedPackage と小文字 64 文字の SHA-256 hex digest が少なくとも 1 つ必要です。すべての current signer は allowlist に含まれていなければなりません。iOS の appIdentity は unsupported を返します。unsupported/error を notDetected に変換せず、アプリ側で fallback、step-up、telemetry policy を決めてください。

Schema と policy​

type Assessment = {
  schemaVersion: number;
  signals: {code: string; status: 'detected' | 'notDetected' | 'unsupported' | 'error'; confidence: string}[];
  durationMs: number;
};

Bridge は status と confidence を保持しますが、アプリのロック、process 終了、UI 表示、network request は行いません。detector、confidence、context に基づく policy はクライアントアプリが決定します。iOS は appIdentity、storeAttestation、missingMotionSensors、batteryUnavailable をサポートしません。

Example とテスト​

cd packages/tei-shield-expo
npm ci
npm run build
npm test
cd example
npm install
npx expo prebuild
npx expo run:android
# または npx expo run:ios

TypeScript test は fake runtime で contract と lifecycle を確認します。development build、release/R8、foreground、実際の署名証明書は検証ガイドに従って実機でも確認してください。
