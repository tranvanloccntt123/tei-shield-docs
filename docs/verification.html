A host-only timing sample of 50 debug-core assessments measured median 0.699 ms and p95 0.946 ms. This is not a mobile performance claim: detector coverage, loaded images, device hardware and build mode differ.

Server scenarios cover simultaneous replay (exactly one committed operation), stale/wrong-session/wrong-user/wrong-purpose challenges, invalid signatures, unknown/revoked devices, provider failure rollback, exact HTTP body/query preservation, increasing iOS counters, current signing-certificate allowlists, request hash mismatch, and development/production separation. Apple enrollment fixtures contain real certificate chains; tests run at the certificates' historical validity dates and also assert rejection after expiry. Assertions and Android proofs use actual ECDSA cryptography in tests. Test fixtures do not exercise a live provider account belonging to this project.

Runtime note​

An initial iOS Simulator test-host launch stalled in dyld while opening dependencies, before application code executed. Rebuilding with derived products under /tmp/tei-shield-ios-tests resolved the launch issue and the runtime test passed. The workspace is on an external volume; that path change was sufficient on this host. The test confirms sdkTextIntegrity: notDetected and emulator: detected in the running framework.

Remaining device acceptance​

These checks require developer configuration and physical devices and have not been claimed as passed:

  • Install the actual Android package via a Google Play test track, link the Google Cloud project, configure Application Default Credentials and signing digests, then run enrollment and protected requests against live Play Integrity.
  • Enable App Attest for the actual Apple App ID, configure the App ID prefix and Bundle ID, then test development and production distributions separately on supported iPhones.
  • Verify clean-device false positives, rooted/jailbroken lab devices, real debugger attachment, injected instrumentation and patched SDK text; preserve negative and unsupported results separately.
  • Test Android signing-key rotation on actual packages, app reinstall, restored backups, missing/invalidated keys, lost enrollment responses and explicit reset/re-enrollment.
  • Exercise offline/provider outages, request reordering, session rotation and delivery-response loss at the application networking layer.
  • Measure p50/p95 assessment/signing time, CPU, memory and foreground transitions on the oldest supported devices. Device crypto protection levels and attestation latency must be measured rather than inferred from emulators.

Reproduction​

Use the commands in the README. For iOS framework runtime verification:

xcodebuild -project ios/TEIShield.xcodeproj -scheme TEIShieldSample \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath /tmp/tei-shield-ios-tests \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- test

CI contains the PostgreSQL, C++, Kotlin, JNI, Swift, framework and packaging jobs. The workflow has been authored but has not been run on GitHub in this session.
