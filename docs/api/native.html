Android and iOS API

Import Kotlin types from dev.tei.shield or Swift types from TEIShield. This page describes the repository's native 0.1.0 source; confirm your installed artifact exposes these methods. Installation is covered by Android and iOS.

Use ShieldCheck.entries.toSet() or AssessmentOptions.all(identity) for all checks. Enum names and wire codes are mapped in Getting started. ShieldCheck.code and .confidence are public; the native mask is internal.

Android methods​

All methods below are suspend; call from an application-owned coroutine. Assessment work switches to Dispatchers.Default; observer attachment/removal switches to Dispatchers.Main. The SDK stores context.applicationContext.

CallResultBehavior
TeiShield.check(context, check, appIdentity = null)SignalOne check, no observer; identity required for APP_IDENTITY
TeiShield.assess(context, options)AssessmentOne selection, no instance/cache/observer
TeiShield.initialize(context, options, runPolicy = ShieldRunPolicy())TeiShieldStores defaults; optional initial and foreground work
TeiShield.initialize(context, config)TeiShieldLegacy: all 12 checks, immediate assessment, foreground observer
sdk.assess()AssessmentRuns stored selection and updates lastAssessment
sdk.assess(options)AssessmentOne-call replacement; updates latest result, preserves defaults
sdk.close()UnitRemoves observer, cancels owned scope, later instance assessment throws IllegalStateException
sdk.lastAssessmentAssessment?Read-only to callers; null until success, retained after close

Instance assessments use a mutex. Static calls do not share that mutex. Android native has no instance check method; use the static method or sdk.assess(AssessmentOptions(...)).

import dev.tei.shield.*

// Inside a suspend function with an Android Context named context.
val sdk = TeiShield.initialize(
    context,
    AssessmentOptions(setOf(ShieldCheck.EMULATOR, ShieldCheck.SDK_TEXT_INTEGRITY)),
    ShieldRunPolicy(assessOnInitialize = true),
)
try {
    val initial = requireNotNull(sdk.lastAssessment)
    val debuggerOnly = sdk.assess(AssessmentOptions(setOf(ShieldCheck.DEBUGGER)))
    val defaultsAgain = sdk.assess()
} finally {
    sdk.close()
}

Native foreground observation uses ProcessLifecycleOwner.onStart. Attaching an observer to an already started lifecycle can trigger an initial callback; do not assume exactly one startup assessment when both flags are enabled. There is no public native result stream. Read the latest property or call assess() when the UI needs a new result.

close() is idempotent, but is not a detector cancellation/join API. A manually launched call already past the closed check can complete and update lastAssessment. This differs from the framework clients' late-result rejection. Native automatic coroutine failures have no public onError hook; own manual scheduling if your app needs explicit error delivery for each run.

Kotlin options use read-only Set types without defensive copying. Pass immutable sets and do not mutate a backing MutableSet after configuration.

Swift has no instance check method or identity configuration. Legacy initialization selects 10 checks: all except missingMotionSensors and batteryUnavailable. Configurable .all selects all 12, including unsupported results.

import TEIShield

let sdk = await TeiShield.initialize(
    options: AssessmentOptions(checks: [.emulator, .sdkTextIntegrity]),
    runPolicy: ShieldRunPolicy(assessOnInitialize: true)
)
let initial = await sdk.lastAssessment
let selected = await sdk.assess(options: AssessmentOptions(checks: [.injectedImages]))
await sdk.close()

TeiShield is an actor; work executes in a detached utility task. Actor isolation does not serialize the entire duration across await: overlapping calls can finish in a different order, and lastAssessment reflects the latest completion. Await calls sequentially if ordering matters. Foreground observation listens to UIApplication.willEnterForegroundNotification; it does not publish a SwiftUI/Combine event. close() neither cancels existing tasks nor permanently closes the actor.

Error boundary​

Detector inability can produce a successful Assessment containing status: "error"; catching exceptions alone is insufficient. Configuration or runtime integration failures can fail a call instead. Swift configurable assessment methods do not throw; invalid native JSON/missing native signals map to per-check error. Android converts some native/parsing exceptions into per-check error, but does not guarantee every linkage/runtime failure becomes a signal. Diagnose both channels using Troubleshooting.
