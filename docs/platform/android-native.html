Tích hợp Android native

Hướng dẫn này dùng Android SDK io.github.tranvanlocntt123:shield:0.1.0 từ Maven Central. API Kotlin chạy trên Android 8 trở lên và native library có sẵn cho arm64-v8a và x86_64.

Yêu cầu​

Thành phầnPhiên bản của SDK
minSdk26 (Android 8.0)
compileSdk35 trong project mẫu
JDK/KotlinJDK 17, Kotlin JVM target 17
ABI trong AARarm64-v8a, x86_64
Dependency runtimeCoroutines Android 1.10.2, Lifecycle Process 2.8.7

Nếu build SDK từ source, cần thêm Android NDK 28.2.13676358 và CMake 3.22.1. Nếu chỉ dùng dependency Maven, app không cần tích hợp CMake/NDK.

Thêm dependency Maven​

Đảm bảo project app có google() và mavenCentral() trong dependencyResolutionManagement:

settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}

Khai báo dependency:

app/build.gradle.kts
dependencies {
    implementation("io.github.tranvanlocntt123:shield:0.1.0")
}

POM Maven tự khai báo các dependency runtime (kotlin-stdlib, coroutines Android và Lifecycle Process), nên app không cần khai báo lại chúng.

Cấu hình certificate​

ShieldConfig bắt buộc có package ID và ít nhất một SHA-256 digest dạng hex viết thường, đúng 64 ký tự:

private const val RELEASE_CERT_SHA256 = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"

private fun shieldConfig() = ShieldConfig(
    expectedPackage = BuildConfig.APPLICATION_ID,
    signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
)

Thay giá trị mẫu bằng digest của certificate đang ký APK. Có thể xem digest từ APK release bằng:

apksigner verify --print-certs app-release.apk

Chuẩn hóa digest về lowercase và bỏ dấu : trước khi đưa vào ShieldConfig. Khi xoay signing key, thêm digest mới trong giai đoạn chuyển tiếp; SDK yêu cầu tất cả current signers của APK đều nằm trong allowlist. Signing history cũ không tự động được chấp nhận.

Chọn detector​

Gọi trực tiếp khi app chỉ cần một kết quả hoặc không muốn SDK tự chạy lúc foreground:

val emulator = TeiShield.check(applicationContext, ShieldCheck.EMULATOR)

val assessment = TeiShield.assess(
    applicationContext,
    AssessmentOptions(
        checks = setOf(ShieldCheck.EMULATOR, ShieldCheck.SDK_TEXT_INTEGRITY),
    ),
)

EMULATOR chỉ đọc Android build properties; không gọi native assessment, PackageManager, sensor hay battery receiver. Chọn APP_IDENTITY thì thêm AppIdentityConfig; thiếu config sẽ ném IllegalArgumentException trước khi detector chạy.

val options = AssessmentOptions(
    checks = setOf(ShieldCheck.APP_IDENTITY, ShieldCheck.EMULATOR),
    appIdentity = AppIdentityConfig(
        expectedPackage = BuildConfig.APPLICATION_ID,
        signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
    ),
)
val shield = TeiShield.initialize(
    applicationContext,
    options,
    ShieldRunPolicy(assessOnInitialize = false, reassessOnForeground = false),
)

shield.assess() dùng lựa chọn đã lưu; shield.assess(options) chạy lựa chọn khác một lần và không thay đổi lựa chọn mặc định. Instance configurable có lastAssessment == null cho tới lần assessment hoàn tất.

Khởi tạo một instance cho process​

Đặt instance ở Application, không ở từng Activity/Fragment. API legacy initialize(config:) đã chạy một assessment ban đầu và đăng ký theo dõi foreground.

ShieldApplication.kt
class ShieldApplication : Application() {
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.Default)

    val shield: Deferred<TeiShield> = scope.async(start = CoroutineStart.LAZY) {
        TeiShield.initialize(
            context = this@ShieldApplication,
            config = shieldConfig(),
        )
    }

    private fun shieldConfig() = ShieldConfig(
        expectedPackage = BuildConfig.APPLICATION_ID,
        signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
    )
}

Khai báo Application trong manifest của app:

AndroidManifest.xml
<application
    android:name=".ShieldApplication"
    ... />

Đọc assessment​

MainActivity.kt
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        lifecycleScope.launch {
            val sdk = (application as ShieldApplication).shield.await()
            val assessment = sdk.assess()

            assessment.signals.forEach { signal ->
                Log.i("TEIShield", "${signal.code}: ${signal.status}")
            }
        }
    }
}

Vì assess() đã chạy trên dispatcher background, không cần tự bọc bằng Dispatchers.IO. UI chỉ nên nhận kết quả đã được chuyển về main thread bởi lifecycleScope.

Vòng đời và đóng SDK​

TeiShield.initialize(config:) tự đăng ký ProcessLifecycleOwner và gọi lại assess() khi process trở lại foreground. Với API configurable, chỉ bật hành vi này bằng ShieldRunPolicy(reassessOnForeground = true).

Gọi close() khi owner của process kết thúc hoặc khi app chủ động bỏ session SDK:

scope.launch {
    (application as ShieldApplication).shield.await().close()
}

Không gọi close() trong Activity.onDestroy() nếu activity chỉ bị recreate do xoay màn hình; việc đó sẽ làm mất instance dùng chung.

Diễn giải signal Android​

Các signal thường gặp gồm debugger, injectedImages, systemWritableMount, privilegedFiles, libcPointer, sdkTextIntegrity, emulator, missingMotionSensors, batteryUnavailable, appIdentity và storeAttestation.

  • appIdentity là notDetected khi package ID đúng và mọi current signer đều khớp allowlist.
  • emulator có thể là detected trên emulator; đây không phải bằng chứng root/jailbreak.
  • storeAttestation là unsupported trong API public hiện tại; không biến nó thành notDetected.
  • error và unsupported phải đi theo nhánh fallback/step-up của app, không được coi là pass.

Không khóa người dùng chỉ vì một signal heuristic. Hãy kết hợp nhiều tín hiệu với risk engine và yêu cầu xác minh bổ sung cho thao tác nhạy cảm.

R8/ProGuard và release​

AAR đã kèm consumer rule để giữ dev.tei.shield.NativeBridge. Không đổi package/class này hoặc loại bỏ rule khi bật R8. Trước khi phát hành:

  1. Build release bằng signing key thật.
  2. Kiểm tra ABI của APK/AAB và digest signer.
  3. Chạy assessment trên emulator và ít nhất một thiết bị thật.
  4. Lưu error/unsupported tách biệt với notDetected trong telemetry đã redaction.

SDK local không thay thế Play Integrity. Nếu server cần bằng chứng store, triển khai luồng server theo TEI1 wire protocol và Trust model; bản 0.1.0 chưa expose API tạo proof trong TeiShield.
