Android native integration

This guide uses Android SDK io.github.tranvanlocntt123:shield:0.1.0 from Maven Central. The Kotlin API runs on Android 8 or later, and the native library is available for arm64-v8a and x86_64.

Requirements​

ComponentSDK version
minSdk26 (Android 8.0)
compileSdk35 in the sample project
JDK/KotlinJDK 17, Kotlin JVM target 17
AAR ABIarm64-v8a, x86_64
Runtime dependenciesCoroutines Android 1.10.2, Lifecycle Process 2.8.7

When building the SDK from source, also install Android NDK 28.2.13676358 and CMake 3.22.1. An app using the Maven dependency does not need to integrate CMake or the NDK.

Add the Maven dependency​

Make sure the app project has google() and mavenCentral() in dependencyResolutionManagement:

settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}

Declare the dependency:

app/build.gradle.kts
dependencies {
    implementation("io.github.tranvanlocntt123:shield:0.1.0")
}

The Maven POM declares the runtime dependencies (kotlin-stdlib, Android coroutines, and Lifecycle Process), so the app does not need to declare them again.

Configure the certificate​

ShieldConfig requires a package ID and at least one lowercase 64-character SHA-256 hex digest:

private const val RELEASE_CERT_SHA256 = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"

private fun shieldConfig() = ShieldConfig(
    expectedPackage = BuildConfig.APPLICATION_ID,
    signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
)

Replace the sample value with the digest of the certificate signing the APK. Read a release APK digest with:

apksigner verify --print-certs app-release.apk

Normalize the digest to lowercase and remove : before passing it to ShieldConfig. During signing-key rotation, add the new digest during the transition; the SDK requires all current signers of the APK to be in the allowlist. Old signing history is not accepted automatically.

Select detectors​

Call the SDK directly when the app needs one result or does not want automatic foreground runs:

val emulator = TeiShield.check(applicationContext, ShieldCheck.EMULATOR)

val assessment = TeiShield.assess(
    applicationContext,
    AssessmentOptions(
        checks = setOf(ShieldCheck.EMULATOR, ShieldCheck.SDK_TEXT_INTEGRITY),
    ),
)

EMULATOR reads only Android build properties; it does not call native assessment, PackageManager, sensors, or the battery receiver. When selecting APP_IDENTITY, add AppIdentityConfig; without it, IllegalArgumentException is thrown before the detector runs.

val options = AssessmentOptions(
    checks = setOf(ShieldCheck.APP_IDENTITY, ShieldCheck.EMULATOR),
    appIdentity = AppIdentityConfig(
        expectedPackage = BuildConfig.APPLICATION_ID,
        signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
    ),
)
val shield = TeiShield.initialize(
    applicationContext,
    options,
    ShieldRunPolicy(assessOnInitialize = false, reassessOnForeground = false),
)

shield.assess() uses the stored selection; shield.assess(options) runs a different selection once and does not change the default. A configurable instance has lastAssessment == null until an assessment completes.

Initialize one instance per process​

Keep the instance in Application, not in each Activity or Fragment. The legacy initialize(config:) API runs an initial assessment and registers foreground observation.

ShieldApplication.kt
class ShieldApplication : Application() {
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.Default)

    val shield: Deferred<TeiShield> = scope.async(start = CoroutineStart.LAZY) {
        TeiShield.initialize(
            context = this@ShieldApplication,
            config = shieldConfig(),
        )
    }

    private fun shieldConfig() = ShieldConfig(
        expectedPackage = BuildConfig.APPLICATION_ID,
        signingCertificateSha256 = setOf(RELEASE_CERT_SHA256),
    )
}

Declare the Application in the app manifest:

AndroidManifest.xml
<application
    android:name=".ShieldApplication"
    ... />

Read an assessment​

MainActivity.kt
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        lifecycleScope.launch {
            val sdk = (application as ShieldApplication).shield.await()
            val assessment = sdk.assess()

            assessment.signals.forEach { signal ->
                Log.i("TEIShield", "${signal.code}: ${signal.status}")
            }
        }
    }
}

Because assess() already runs on a background dispatcher, you do not need to wrap it in Dispatchers.IO. The UI receives the result on the main thread through lifecycleScope.

Lifecycle and closing the SDK​

TeiShield.initialize(config:) registers ProcessLifecycleOwner and calls assess() when the process returns to the foreground. With the configurable API, enable this behavior only through ShieldRunPolicy(reassessOnForeground = true).

Call close() when the process owner ends or the app deliberately discards the SDK session:

scope.launch {
    (application as ShieldApplication).shield.await().close()
}

Do not call close() from Activity.onDestroy() when the activity is only recreated for rotation; doing so destroys the shared instance.

Interpret Android signals​

Common signals include debugger, injectedImages, systemWritableMount, privilegedFiles, libcPointer, sdkTextIntegrity, emulator, missingMotionSensors, batteryUnavailable, appIdentity, and storeAttestation.

  • appIdentity is notDetected when the package ID is correct and every current signer matches the allowlist.
  • emulator can be detected on an emulator; this is not proof of root or jailbreak.
  • storeAttestation is unsupported in the current public API; do not convert it to notDetected.
  • Route error and unsupported through the app's fallback/step-up path; do not treat them as a pass.

Do not lock out a user because of a single heuristic signal. Combine multiple signals with a risk engine and require additional verification for sensitive actions.

R8/ProGuard and release​

The AAR includes a consumer rule that keeps dev.tei.shield.NativeBridge. Do not change this package/class or remove the rule when enabling R8. Before release:

  1. Build a release with the real signing key.
  2. Check the APK/AAB ABI and signer digest.
  3. Run assessment on an emulator and at least one physical device.
  4. Keep error/unsupported separate from notDetected in redacted telemetry.

The local SDK does not replace Play Integrity. If the server needs store evidence, implement the server flow described in the TEI1 wire protocol and Trust model; version 0.1.0 does not expose an API for creating proof in TeiShield.
