Integrate TEI Shield

TEI Shield is a local-only risk assessment SDK. In version 0.1.0, the SDK does not call a backend, require an account, or create Play Integrity/App Attest proof. The host application receives device-local signals and decides its own policy.

Common flow​

  1. Add the artifact for the platform and check the minimum SDK: Android API 26 (Android 8) or iOS 15.
  2. For a one-off check, call check() or assess(options:) directly; these APIs do not create an instance or observer.
  3. For long-lived use, initialize one instance per process. Do not create a new instance for every screen or render.
  4. The legacy initialize(config:) API still assesses immediately and reassesses on foreground. The configurable API only runs automatically when the corresponding ShieldRunPolicy flags are enabled.
  5. Map Assessment into the app's policy. Never treat unsupported or error as a trusted device.
One-off:  check() / assess(options) ──> Assessment ──> App policy

Reuse:    initialize(options, runPolicy)
                         │
                  assess() on demand,
              at initialization or foreground
                         │
                         └───────────────> Assessment ──> App policy

Selecting detectors and when to run​

An emulator-only check does not need a package ID, certificate, native assessment, or lifecycle observer:

val emulator = TeiShield.check(applicationContext, ShieldCheck.EMULATOR)
let emulator = await TeiShield.check(.emulator)

Use AssessmentOptions(checks: ...) to select multiple detectors. On Android, add AppIdentityConfig only when the list includes APP_IDENTITY; without it, the SDK reports an error before running. An empty list returns an empty assessment. Results contain only requested detectors, so a missing signal means that detector did not run.

Result schema​

{
  "schemaVersion": 1,
  "signals": [
    { "code": "sdkTextIntegrity", "status": "notDetected", "confidence": "high" },
    { "code": "emulator", "status": "detected", "confidence": "high" }
  ],
  "durationMs": 1.4
}
FieldMeaning
schemaVersionResult schema version; currently 1.
signals[].codeCheck name, such as debugger, injectedImages, or appIdentity.
signals[].statusdetected, notDetected, unsupported, or error.
signals[].confidenceDetector confidence (high, medium, low), not a probability.
durationMsLocal assessment time; an observation, not a mobile SLA.

detected means only that the detector observed its indicator. notDetected does not prove that the device is clean. A single detector is not enough reason to lock an account or reject a user.

Minimal policy example:

error / unsupported  -> record the state; use fallback or step-up
detected             -> require additional verification for sensitive actions
notDetected          -> continue normal business policy

What the SDK does not do​

  • It does not send telemetry, evidence, tokens, or device data outside the app.
  • It does not authenticate users or authorize server APIs.
  • It has no API for enrollment, assertion creation, or HTTP request signing in the current version.
  • It does not claim that a device has secure hardware based on a local signal alone.

For server-side protection, see the TEI1 wire protocol. The server must independently validate the session, challenge, signature/evidence, and transaction; it must not accept a local Assessment as a trust anchor.

Integration security​

  • Do not log raw evidence, private keys, challenges, or sensitive bodies.
  • Preserve body bytes and the raw path/query when implementing proof requests; do not parse and reserialize JSON.
  • Android must configure the package ID and SHA-256 digest of every current signer in the allowlist.
  • For iOS release, use the binary package from artifacts/ios/; the source Swift Package is for development/testing and reports sdkTextIntegrity: unsupported because it does not run the post-link sealing step.
  • Distinguish simulator/emulator results from results on physical devices.

Detector coverage and known limitations are documented in the Trust model. The release verification process is in the Verification record.
