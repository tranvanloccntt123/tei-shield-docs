Tích hợp TEI Shield

TEI Shield là SDK đánh giá rủi ro local-only. Ở phiên bản 0.1.0, SDK không gọi backend, không yêu cầu tài khoản và không tự tạo Play Integrity/App Attest proof. Ứng dụng chủ nhận các tín hiệu quan sát tại thiết bị, sau đó tự quyết định policy.

Chọn hướng tích hợp​

Luồng dùng chung​

  1. Thêm artifact đúng nền tảng và kiểm tra min SDK: Android API 26 (Android 8) hoặc iOS 15.
  2. Với kiểm tra một lần, gọi check() hoặc assess(options:) trực tiếp; hai API này không tạo instance hay observer.
  3. Khi cần dùng lâu dài, khởi tạo một instance cho mỗi process. Không tạo instance mới cho mỗi màn hình hay mỗi lần render.
  4. API initialize(config:) cũ vẫn assessment ngay và tự chạy lại lúc foreground. API configurable chỉ tự chạy khi ShieldRunPolicy bật các cờ tương ứng.
  5. Ánh xạ Assessment vào policy của app. Không coi unsupported hoặc error là thiết bị tin cậy.
Một lần:  check() / assess(options) ──> Assessment ──> App policy

Dùng lại:  initialize(options, runPolicy)
                         │
                  assess() theo yêu cầu,
               lúc khởi tạo hoặc foreground
                         │
                         └───────────────> Assessment ──> App policy

Chọn detector và thời điểm chạy​

Chỉ cần kiểm tra emulator không cần package ID, certificate, native assessment hay lifecycle observer:

val emulator = TeiShield.check(applicationContext, ShieldCheck.EMULATOR)
let emulator = await TeiShield.check(.emulator)

Dùng AssessmentOptions(checks: ...) để chọn nhiều detector. Trên Android, chỉ thêm AppIdentityConfig khi danh sách có APP_IDENTITY; nếu thiếu, SDK báo lỗi trước khi chạy. Một danh sách rỗng trả assessment rỗng. Kết quả chỉ chứa detector được yêu cầu, theo đó signal không xuất hiện có nghĩa là detector không được chạy.

React Native và Flutter truyền các giá trị ở cột Signal code qua bridge. Detector tự viết bởi app chưa thuộc API này; app có thể kết hợp signal trả về với policy riêng của mình.

Schema kết quả​

{
  "schemaVersion": 1,
  "signals": [
    { "code": "sdkTextIntegrity", "status": "notDetected", "confidence": "high" },
    { "code": "emulator", "status": "detected", "confidence": "high" }
  ],
  "durationMs": 1.4
}
TrườngÝ nghĩa
schemaVersionPhiên bản schema kết quả; hiện tại là 1.
signals[].codeTên kiểm tra, ví dụ debugger, injectedImages, appIdentity.
signals[].statusdetected, notDetected, unsupported hoặc error.
signals[].confidenceĐộ tin cậy của detector (high, medium, low). Không phải xác suất.
durationMsThời gian assessment local; dùng để quan sát, không phải SLA mobile.

detected chỉ có nghĩa là detector quan sát được indicator tương ứng. notDetected không chứng minh thiết bị sạch. Một detector đơn lẻ cũng không đủ cơ sở để khóa tài khoản hoặc từ chối người dùng.

Ví dụ policy tối thiểu:

error / unsupported  -> ghi nhận trạng thái, dùng fallback hoặc step-up
detected             -> yêu cầu xác minh bổ sung cho hành động nhạy cảm
notDetected          -> tiếp tục policy nghiệp vụ thông thường

Những gì SDK không làm​

  • Không gửi telemetry, evidence, token hoặc dữ liệu thiết bị ra ngoài.
  • Không xác thực người dùng và không cấp quyền cho API server.
  • Không có API để enrollment, tạo assertion hoặc ký HTTP request ở phiên bản hiện tại.
  • Không khẳng định thiết bị có phần cứng an toàn chỉ dựa trên một tín hiệu local.

Nếu cần bảo vệ thao tác server, hãy xem TEI1 wire protocol. Server phải xác thực session, challenge, signature/evidence và transaction độc lập; không chấp nhận Assessment local như một trust anchor.

Bảo mật khi tích hợp​

  • Không ghi raw evidence, private key, challenge hoặc body nhạy cảm vào log.
  • Giữ nguyên bytes của body và raw path/query nếu app tự triển khai request proof; không parse rồi serialize JSON lại.
  • Android phải cấu hình đúng package ID và SHA-256 của mọi current signer trong allowlist.
  • iOS release nên dùng binary package từ artifacts/ios/; source Swift Package phục vụ phát triển/test và báo sdkTextIntegrity: unsupported vì không chạy bước seal sau link.
  • Hãy phân biệt rõ kết quả trên simulator/emulator với kết quả trên thiết bị thật.

Phạm vi detector và các giới hạn đã biết nằm trong Trust model. Quy trình kiểm chứng release nằm trong Verification record.
