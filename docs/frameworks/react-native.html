Tích hợp React Native / Expo

Module @teiresource/shield-expo được phân phối trực tiếp qua npm registry. Android resolve SDK io.github.tranvanlocntt123:shield:0.1.0 từ Maven Central; Swift bridge dùng XCFramework được đóng gói trong package. TypeScript quản lý lựa chọn detector, client và lifecycle.

Module sử dụng Expo Modules API, dùng được với Expo và React Native đã cài Expo Modules. Cần development build/native build; Expo Go tiêu chuẩn không chứa binary native của TEI Shield. Baseline example là Expo SDK 55, React Native 0.83, React 19.2; Android API 26+ và iOS 15.1+ (giữ target cao hơn do Expo yêu cầu).

Cài vào Expo app​

Cài đặt package trực tiếp từ npm:

npx expo install @teiresource/shield-expo
npx expo install expo-dev-client

Hoặc sử dụng npm / yarn / pnpm:

npm install @teiresource/shield-expo
npx expo install expo-dev-client

Thêm config plugin vào app.json:

app.json
{
  "expo": {
    "plugins": ["@teiresource/shield-expo"]
  }
}

Tạo native project và chạy development build:

npx expo prebuild
npx expo run:android
# Hoặc:
npx expo run:ios

AAR hỗ trợ arm64-v8a và x86_64. Đặt reactNativeArchitectures=arm64-v8a,x86_64 trong Gradle properties hoặc expo-build-properties với android.buildArchs: ['arm64-v8a', 'x86_64'] trước release. Autolinking tự động đăng ký module Kotlin/Swift. Config plugin nâng giá trị deployment target quá thấp đã cấu hình trong Gradle/Podfile properties; nếu chưa đặt Android minSdk thì thêm 26, còn iOS giữ default của Expo SDK. Để thay compileSdk, deployment target cao hơn hoặc build settings khác, app dùng expo-build-properties như bình thường.

Với EAS Build: Gradle resolve io.github.tranvanlocntt123:shield:0.1.0 từ Maven Central; XCFramework iOS vẫn nằm trong npm package. Config plugin chỉ cấu hình minSdk/deployment target, không thêm repository local. Sau khi cài hoặc nâng cấp package, chạy lại npx expo prebuild để cập nhật native module. Không cần thêm cùng TEIShield qua Swift Package Manager: podspec của module đã link/embed XCFramework.

React Native đã có native project​

Cài đặt package vào app:

npm install @teiresource/shield-expo

Nếu dự án chưa tích hợp Expo Modules, hãy cài Expo Modules vào React Native, sau đó chạy:

npx pod-install

Giữ Android minSdk >= 26 và iOS target >= 15.1, hoặc mức cao hơn React Native yêu cầu. Không cần đăng ký ReactPackage thủ công (Expo Modules autolinking tự động xử lý). Host Android phải có google() và mavenCentral() trong dependencyResolutionManagement.repositories; không cần thêm repository từ node_modules.

Bảo mật bản release với Hermes và R8​

Bản release của ứng dụng React Native/Expo nên bật cả hai lớp bảo vệ:

  • Hermes biên dịch JavaScript/TypeScript thành bytecode, thay vì đóng gói source dễ đọc trong APK.
  • R8 shrink, tối ưu và obfuscate mã Java/Kotlin native, đổi tên class, method và field thành các tên ngắn như a, b, c.

R8 không làm reverse engineering bất khả thi, nhưng làm việc phân tích APK khó hơn đáng kể. Đây là lớp bảo vệ cho artifact release, không thay thế việc không hard-code secret, kiểm soát API và xác thực ở server.

Cấu hình R8 cho Expo​

Cài config plugin nếu app chưa có:

npx expo install expo-build-properties

Thêm hai tùy chọn Android vào app.json hoặc app.config.js:

app.json
{
  "expo": {
    "plugins": [
      "@teiresource/shield-expo",
      [
        "expo-build-properties",
        {
          "android": {
            "enableMinifyInReleaseBuilds": true,
            "enableShrinkResourcesInReleaseBuilds": true
          }
        }
      ]
    ]
  }
}

enableMinifyInReleaseBuilds bật R8 cho release build. enableShrinkResourcesInReleaseBuilds loại bỏ resource không được sử dụng để giảm kích thước APK và bề mặt cần phân tích. Với các Expo SDK hiện tại, dùng hai thuộc tính này thay cho tên cũ enableProguardInReleaseBuilds.

Build và xác minh​

Nếu dự án đã có thư mục android/ được sinh từ cấu hình cũ, chạy prebuild lại trước khi build release:

rm -rf android
npx expo run:android --variant release

Không chỉ dựa vào log build. Kiểm tra các dấu hiệu sau:

# R8 đã chạy thì mapping file phải tồn tại
ls -la android/app/build/outputs/mapping/release/mapping.txt

# Phải thấy minifyEnabled true
grep "minifyEnabled" android/app/build.gradle

Giữ mapping.txt an toàn cùng với artifact release để giải mã stack trace sau này. Có thể kiểm tra thêm bằng JADX:

jadx android/app/build/outputs/apk/release/app-release.apk -d /tmp/decompiled
ls /tmp/decompiled/sources/

Tên package/class native sau obfuscation thường ngắn hơn và không còn phản ánh tên nghiệp vụ. Việc kiểm tra này chỉ xác nhận lớp native; Hermes bytecode vẫn cần được kiểm tra trong APK nếu cần audit artifact.

Kiểm thử bắt buộc​

R8 có thể loại bỏ class được thư viện truy cập qua reflection. Vì vậy, luôn cài bản release lên thiết bị thật và kiểm tra các luồng chính, đặc biệt là khởi tạo module, autolinking, assessment và các thư viện native khác. Nếu debug chạy được nhưng release crash, xem log:

adb logcat | grep -i "error\|crash\|exception"

Sau đó bổ sung keep rule cần thiết cho thư viện gây lỗi, đồng thời giữ consumer rule của TEI Shield theo hướng dẫn Android native. Checklist release đầy đủ nằm trong hướng dẫn kiểm chứng.

Tham khảo thêm: Enabling Code Obfuscation in Expo React Native: R8 Shrinking & Obfuscation.

Kiểm tra một lần​

import {assess, check} from '@teiresource/shield-expo';

const emulator = await check('emulator');
const result = await assess({checks: ['emulator', 'sdkTextIntegrity']});
const empty = await assess(); // signals: []; không khởi tạo observer

SHIELD_CHECKS chứa 12 mã public: debugger, injectedImages, systemWritableMount, privilegedFiles, libcPointer, sdkTextIntegrity, toolPort, appIdentity, emulator, missingMotionSensors, batteryUnavailable, storeAttestation. Chỉ detector được chọn xuất hiện trong kết quả. Code không hợp lệ bị từ chối ở TypeScript và native.

Tùy biến từ client app​

import {createClient, SHIELD_CHECKS} from '@teiresource/shield-expo';

// Lấy từ cấu hình build/environment của app, dùng certificate ký app thực tế.
const identity = {
  expectedPackage: 'com.company.mobile',
  signingCertificateSha256: [releaseCertificateSha256, nextCertificateSha256],
};

const client = await createClient({
  options: {
    checks: ['appIdentity', 'emulator', 'sdkTextIntegrity'],
    appIdentity: identity,
  },
  runPolicy: {assessOnInitialize: false, reassessOnForeground: true},
  onAssessment: assessment => appRiskPolicy.consume(assessment),
  onError: error => reportAssessmentFailure(error),
});

const configured = await client.assess();
const once = await client.assess({checks: ['debugger']});
const sameDefaults = await client.assess();
const all = await client.assess({checks: SHIELD_CHECKS, appIdentity: identity});
const single = await client.check('appIdentity'); // dùng identity mặc định của client
console.log(client.lastAssessment);
client.close();

releaseCertificateSha256, nextCertificateSha256, appRiskPolicy và reportAssessmentFailure là giá trị/hàm do app cung cấp. Không có certificate mẫu được hard-code trong bridge. Android yêu cầu expectedPackage không rỗng và ít nhất một digest SHA-256 hex lowercase 64 ký tự khi chọn appIdentity. Các current signer đều phải thuộc allowlist; truyền nhiều digest để xoay key. Với iOS, appIdentity vẫn trả unsupported và không yêu cầu cấu hình Android. Nếu truyền identity, shape của nó được kiểm tra trên cả hai platform.

Tùy chọnHành vi
options.checksDanh sách riêng của client, snapshot khi tạo; rỗng chạy 0 detector
options.appIdentityPackage/certificate do host app cung cấp
assessOnInitializeMặc định false; bật để có kết quả ban đầu trước khi createClient resolve
reassessOnForegroundMặc định false; bật để theo dõi AppState chuyển background/inactive → active
onAssessmentNhận kết quả cho mọi assessment thành công của client
onErrorNhận lỗi từ assessment tự động hoặc callback onAssessment
assess(options)Thay toàn bộ selection cho đúng một lần, không merge hay đổi default
close()Gỡ listener, từ chối request sau đó, bỏ kết quả đang chạy và các request còn đợi

Lời gọi thủ công trả lỗi qua Promise. Foreground liên tiếp được gộp trong lúc assessment tự động đang đợi/chạy; request trên một client chạy tuần tự. close() không dừng detector đã vào native. Client bị đóng không nhận callback/kết quả muộn. Không có background service: lifecycle chỉ hoạt động khi JS runtime đang hoạt động. Giữ client ở scope app/session; tạo client mới để đổi default hoặc run policy. Xem packages/tei-shield-expo/example/App.tsx để xử lý cleanup khi React effect kết thúc trước khi initialize hoàn tất.

Schema và policy​

type Assessment = {
  schemaVersion: number;
  signals: {code: string; status: 'detected' | 'notDetected' | 'unsupported' | 'error'; confidence: string}[];
  durationMs: number;
};

Bridge giữ nguyên status/confidence, không tự khóa app, thoát process, hiển thị UI hay gửi network. Client app quyết định policy theo detector, confidence và ngữ cảnh; unsupported/error không phải notDetected. iOS không hỗ trợ appIdentity, storeAttestation, missingMotionSensors, batteryUnavailable; SDK hiện không cung cấp store proof. Xem trust model.

Lỗi cấu hình có code TEI_SHIELD_INVALID_OPTIONS; chưa link module là TEI_SHIELD_NOT_LINKED; gọi client đã đóng là TEI_SHIELD_CLOSED. Web/desktop trả TEI_SHIELD_UNSUPPORTED_PLATFORM.

Chạy example và kiểm thử​

cd packages/tei-shield-expo
npm ci
npm run build
npm test
cd example
npm install
npx expo prebuild
npx expo run:android
# hoặc npx expo run:ios

Test TypeScript kiểm tra contract/lifecycle bằng runtime giả. Vẫn cần kiểm tra development build, release/R8, foreground và certificate ký thực trên thiết bị theo hướng dẫn kiểm chứng.
