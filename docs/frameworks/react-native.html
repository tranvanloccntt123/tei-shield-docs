React Native / Expo integration

The @teiresource/shield-expo module is distributed directly through the npm registry. Android resolves SDK io.github.tranvanloccntt123:shield:0.1.0 from Maven Central; the Swift bridge uses the XCFramework bundled in the package. TypeScript manages detector selection, the client, and lifecycle.

The module uses the Expo Modules API and works with Expo or React Native projects that have Expo Modules installed. A development/native build is required; standard Expo Go does not contain TEI Shield's native binary. The baseline example uses Expo SDK 55, React Native 0.83, and React 19.2; Android API 26+ and iOS 15.1+ are required (keep targets higher when required by Expo).

Install in an Expo app​

Install the packages from npm:

npx expo install @teiresource/shield-expo
npx expo install expo-dev-client

Or use npm, yarn, or pnpm:

npm install @teiresource/shield-expo
npx expo install expo-dev-client

Add the config plugin to app.json:

app.json
{
  "expo": {
    "plugins": ["@teiresource/shield-expo"]
  }
}

Generate the native project and run a development build:

npx expo prebuild
npx expo run:android
# Or:
npx expo run:ios

The AAR supports arm64-v8a and x86_64. Before release, set reactNativeArchitectures=arm64-v8a,x86_64 in Gradle properties or use expo-build-properties with android.buildArchs: ['arm64-v8a', 'x86_64']. Autolinking registers the Kotlin/Swift module automatically. The config plugin raises a deployment target that is set too low in Gradle/Podfile properties; if Android minSdk is not set, add 26, while iOS keeps the Expo SDK default. Use expo-build-properties as usual for a different compileSdk, a higher deployment target, or other build settings.

With EAS Build, Gradle resolves io.github.tranvanloccntt123:shield:0.1.0 from Maven Central and the iOS XCFramework remains inside the npm package. The config plugin only configures minSdk/deployment target and does not add a local repository. After installing or upgrading the package, run npx expo prebuild again to update the native module. Do not add TEIShield a second time through Swift Package Manager: the module podspec already links and embeds the XCFramework.

React Native with an existing native project​

Install the package in the app:

npm install @teiresource/shield-expo

If the project does not use Expo Modules yet, install Expo Modules into React Native, then run:

npx pod-install

Keep Android minSdk >= 26 and iOS target >= 15.1, or use the higher level required by React Native. You do not need to register a ReactPackage manually; Expo Modules autolinking handles it. The Android host must have google() and mavenCentral() in dependencyResolutionManagement.repositories; no repository from node_modules is required.

Release security with Hermes and R8​

A React Native/Expo release build should enable both protection layers:

  • Hermes compiles JavaScript/TypeScript into bytecode instead of packaging easily readable source in the APK.
  • R8 shrinks, optimizes, and obfuscates native Java/Kotlin code by renaming classes, methods, and fields to short names such as a, b, and c.

R8 does not make reverse engineering impossible, but it makes APK analysis significantly harder. It protects the release artifact; it does not replace avoiding hard-coded secrets, controlling APIs, or authenticating requests on the server.

Configure R8 for Expo​

Install the config plugin if the app does not have it:

npx expo install expo-build-properties

Add the two Android options to app.json or app.config.js:

app.json
{
  "expo": {
    "plugins": [
      "@teiresource/shield-expo",
      [
        "expo-build-properties",
        {
          "android": {
            "enableMinifyInReleaseBuilds": true,
            "enableShrinkResourcesInReleaseBuilds": true
          }
        }
      ]
    ]
  }
}

enableMinifyInReleaseBuilds enables R8 for release builds. enableShrinkResourcesInReleaseBuilds removes unused resources to reduce APK size and the surface available for analysis. With current Expo SDKs, use these properties instead of the old enableProguardInReleaseBuilds name.

Build and verify​

If the project already has an android/ directory generated from older configuration, regenerate it before building release:

npx expo prebuild
npx expo run:android --variant release

Run npx expo prebuild to apply plugin configuration, then inspect the generated diff. Use npx expo prebuild --clean only when native projects are fully reproducible from app configuration and all manual changes are saved; clean regeneration replaces native directories. In a hand-maintained native project, apply the equivalent Gradle settings directly.

Do not rely only on build logs. Check these indicators:

# This mapping file exists when R8 has run
ls -la android/app/build/outputs/mapping/release/mapping.txt

# This must show minifyEnabled true
grep "minifyEnabled" android/app/build.gradle

Keep mapping.txt safe with the release artifact so crash stack traces can be decoded later. You can also inspect the APK with JADX:

jadx android/app/build/outputs/apk/release/app-release.apk -d /tmp/decompiled
ls /tmp/decompiled/sources/

Native package/class names after obfuscation are usually shorter and no longer expose business names. This check only confirms the native layer; inspect Hermes bytecode in the APK as well when performing an artifact audit.

Required release testing​

R8 can remove classes that a library accesses through reflection. Always install the release build on a real device and test the main flows, especially module initialization, autolinking, assessment, and other native libraries. If debug works but release crashes, inspect the logs:

adb logcat | grep -i "error\|crash\|exception"

Add the required keep rule for the failing library, and keep TEI Shield's consumer rule as described in the Android native guide. The complete release checklist is in the verification guide.

Read the original reference: Enabling Code Obfuscation in Expo React Native: R8 Shrinking & Obfuscation.

One-off checks​

import {assess, check} from '@teiresource/shield-expo';

const emulator = await check('emulator');
const result = await assess({checks: ['emulator', 'sdkTextIntegrity']});
const empty = await assess(); // signals: []; no observer is initialized

SHIELD_CHECKS contains 12 public codes: debugger, injectedImages, systemWritableMount, privilegedFiles, libcPointer, sdkTextIntegrity, toolPort, appIdentity, emulator, missingMotionSensors, batteryUnavailable, and storeAttestation. Only selected detectors appear in the result. Invalid codes are rejected by TypeScript and native code.

Configure from the client app​

import {createClient, SHIELD_CHECKS} from '@teiresource/shield-expo';

// Read from the app's build/environment configuration and use the real signing certificate.
const identity = {
  expectedPackage: 'com.company.mobile',
  signingCertificateSha256: [releaseCertificateSha256, nextCertificateSha256],
};

const client = await createClient({
  options: {
    checks: ['appIdentity', 'emulator', 'sdkTextIntegrity'],
    appIdentity: identity,
  },
  runPolicy: {assessOnInitialize: false, reassessOnForeground: true},
  onAssessment: assessment => appRiskPolicy.consume(assessment),
  onError: error => reportAssessmentFailure(error),
});

const configured = await client.assess();
const once = await client.assess({checks: ['debugger']});
const sameDefaults = await client.assess();
const all = await client.assess({checks: SHIELD_CHECKS, appIdentity: identity});
const single = await client.check('appIdentity'); // uses the client's default identity
console.log(client.lastAssessment);
client.close();

releaseCertificateSha256, nextCertificateSha256, appRiskPolicy, and reportAssessmentFailure are supplied by the app. The bridge does not hard-code a sample certificate. Android requires a non-empty expectedPackage and at least one lowercase 64-character SHA-256 hex digest when appIdentity is selected. Every current signer must be in the allowlist; provide multiple digests during key rotation. On iOS, appIdentity returns unsupported and does not require Android configuration. If identity is supplied, its shape is validated on both platforms.

OptionBehavior
options.checksClient-specific selection, snapshotted at creation; an empty list runs zero detectors
options.appIdentityPackage/certificate supplied by the host app
assessOnInitializeDefaults to false; enable it to obtain an initial result before createClient resolves
reassessOnForegroundDefaults to false; enable it to track background/inactive → active transitions in AppState
onAssessmentReceives every successful assessment from the client
onErrorReceives errors from automatic assessment or the onAssessment callback
assess(options)Replaces selection for one call only; it does not merge or change defaults
close()Removes listeners, rejects later requests, and discards in-flight and queued results

Manual calls return errors through a Promise. Consecutive foreground events are coalesced while automatic assessment is waiting or running; requests on one client run sequentially. close() does not stop a detector already running in native code. A closed client does not receive late callbacks or results. There is no background service: lifecycle behavior only runs while the JS runtime is active. Keep the client at app/session scope; create a new client to change defaults or run policy. See packages/tei-shield-expo/example/App.tsx for cleanup when a React effect ends before initialization completes.

Schema and policy​

type Assessment = {
  schemaVersion: number;
  signals: {code: string; status: 'detected' | 'notDetected' | 'unsupported' | 'error'; confidence: string}[];
  durationMs: number;
};

The bridge preserves status and confidence. It does not lock the app, terminate the process, display UI, or send network requests. The client app decides policy using detector, confidence, and context; unsupported/error is not notDetected. iOS does not support appIdentity, storeAttestation, missingMotionSensors, or batteryUnavailable; the SDK currently does not provide store proof. See the trust model.

Configuration errors use TEI_SHIELD_INVALID_OPTIONS; an unlinked module uses TEI_SHIELD_NOT_LINKED; calls on a closed client use TEI_SHIELD_CLOSED. Web/desktop uses TEI_SHIELD_UNSUPPORTED_PLATFORM.

Run the example and tests​

cd packages/tei-shield-expo
npm ci
npm run build
npm test
cd example
npm install
npx expo prebuild
npx expo run:android
# or npx expo run:ios

TypeScript tests check the contract and lifecycle with a fake runtime. Still test the development build, release/R8, foreground behavior, and the real signing certificate on a device using the verification guide.
