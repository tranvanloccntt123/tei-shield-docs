Flutter integration

The tei_shield_flutter plugin is distributed through pub.dev. It registers Android/iOS through Flutter autolinking and uses MethodChannel('dev.tei/shield'). Android resolves SDK io.github.tranvanloccntt123:shield:0.1.0 from Maven Central; the iOS XCFramework is bundled in the package. The bridge calls the two native SDKs directly, while Dart manages the client and automatic run policy.

Requirements: Dart >= 3.6, Flutter >= 3.27, Android API >= 26 / JDK 17, and iOS >= 15 / Swift 5.9. The example was checked with Flutter 3.41.6. The plugin uses CocoaPods for the XCFramework; even when the Flutter host enables Swift Package Manager, keep the CocoaPods fallback for this plugin as described in the Flutter guide.

Install the plugin​

Install from pub.dev:

flutter pub add tei_shield_flutter

Or add it to pubspec.yaml:

pubspec.yaml
dependencies:
  tei_shield_flutter: ^0.1.9

Fetch dependencies:

flutter pub get

Platform configuration​

  • Android:

    • Set minSdk = 26 or higher in android/app/build.gradle.kts or android/app/build.gradle.
    • The AAR supports only arm64-v8a and x86_64. Build an APK with: 
      flutter build apk --target-platform android-arm64,android-x64
      Or configure the matching ABI filters in ndk.abiFilters when building an AAB.
    • The Flutter host needs google() and mavenCentral() in dependencyResolutionManagement.repositories (the default for new Flutter projects). The SDK and runtime dependencies resolve from Maven Central.

  • iOS:

    • Set the iOS deployment target to 15+ in Runner and platform :ios, '15.0' or higher in ios/Podfile.
    • Install Pods: 
      cd ios && pod install && cd ..
    • When Flutter generates the Podfile, keep the project target at 15+ before the first build. Do not add TEIShield again through SPM; the plugin podspec links and embeds the binary XCFramework.

One-off checks​

import 'package:tei_shield_flutter/tei_shield_flutter.dart';

final emulator = await TeiShield.check(ShieldCheck.emulator);
final result = await TeiShield.assess(AssessmentOptions(
  checks: [ShieldCheck.emulator, ShieldCheck.sdkTextIntegrity],
));
final empty = await TeiShield.assess(); // empty signals; no observer

ShieldCheck.values contains all 12 detectors exposed by the native SDK. An empty list runs no detector. Native code rejects invalid check codes or payloads, including direct MethodChannel calls.

Configure from the client app​

final identity = AppIdentityConfig(
  expectedPackage: 'com.company.mobile',
  signingCertificateSha256: [releaseCertificateSha256, nextCertificateSha256],
);
final client = await TeiShieldClient.initialize(
  options: AssessmentOptions(
    checks: [ShieldCheck.appIdentity, ShieldCheck.emulator, ShieldCheck.sdkTextIntegrity],
    appIdentity: identity,
  ),
  runPolicy: const ShieldRunPolicy(
    assessOnInitialize: true,
    reassessOnForeground: true,
  ),
);

// The stream does not replay. The initialize result is stored in lastAssessment.
appRiskPolicy.consume(client.lastAssessment!);
final subscription = client.assessments.listen(
  appRiskPolicy.consume,
  onError: reportAssessmentFailure,
);

final configured = await client.assess();
final once = await client.assess(AssessmentOptions(checks: [ShieldCheck.debugger]));
final originalDefaults = await client.assess();
final all = await client.assess(AssessmentOptions(checks: ShieldCheck.values, appIdentity: identity));
final signer = await client.check(ShieldCheck.appIdentity);

await subscription.cancel();
await client.close();

releaseCertificateSha256, nextCertificateSha256, appRiskPolicy, and reportAssessmentFailure are supplied by the app. The bridge does not hard-code a certificate. Android requires a non-empty package and a lowercase 64-character digest when appIdentity is selected. Multiple digests can be provided during signing-key rotation. iOS returns appIdentity: unsupported; identity is not required, but its shape is still validated when supplied.

API / optionBehavior
AssessmentOptionsCopies checks/certificates into an immutable collection
ShieldRunPolicyBoth flags default to false; the app chooses initial and/or foreground runs
client.assess()Uses the stored selection
client.assess(options)Uses a one-off selection; it does not merge with or replace defaults
client.check(check)Runs one detector with the client's default identity
client.lastAssessmentnull before a successful run, then the latest snapshot
client.assessmentsBroadcast stream for successful results; automatic errors go to the stream error channel
client.close()Removes the observer, closes the stream, and rejects late requests/results

Manual call failures are returned through Future. Add onError to the stream when foreground checks are enabled. Automatic checks follow Flutter's transition to resumed; they do not run only because the plugin first attaches, there is no background service, and no additional native SDK observer is registered. The client serializes requests and coalesces consecutive foreground events while an automatic run is pending. close() does not interrupt a native detector already running, but removes in-flight and queued results. Create a new client to change defaults or run policy.

Keep the client at app/session scope. See packages/tei-shield_flutter/example/lib/main.dart for subscription cleanup and the case where a widget is disposed before initialization completes.

Application schema and policy​

TeiShieldAssessment contains schemaVersion, signals, and durationMs (double). Each signal has code, SignalStatus (detected, notDetected, unsupported, error), and a string confidence. The plugin preserves the data; it does not block the app, choose thresholds, or call a server. The app owns UI, telemetry, step-up, and policy decisions.

Do not convert unsupported/error into a pass. On iOS, appIdentity, storeAttestation, missingMotionSensors, and batteryUnavailable return unsupported. storeAttestation also has no proof on Android at this time. See the trust model.

Invalid Dart configuration returns ArgumentError; an invalid native payload returns PlatformException with code TEI_SHIELD_INVALID_OPTIONS. A detached Android engine receives no late callback and creates a new coroutine scope when reattached. Web/desktop returns UnsupportedError.

Run the example and tests​

cd packages/tei-shield_flutter
flutter pub get
flutter analyze
flutter test
cd example
flutter create --platforms=android,ios --project-name=tei_shield_example --org dev.tei .
# Set minSdk 26 and iOS deployment target 15+ as described above.
flutter run

The example has a button for an emulator-only check and a default detector group. Dart tests mock MethodChannel to check serialization, identity, overrides, stream/lifecycle, and close; use Android/iOS builds and a real device for native coverage according to the verification checklist.

You can run native integration tests on an emulator/simulator with flutter test integration_test/shield_test.dart -d <device-id>. The test covers empty selection, emulator state, store attestation state, and native-boundary validation.
